1. Introduction to the Data Link Layer

Definition

The Data Link Layer (DLL) is the second layer of the OSI reference model. It provides node-to-node delivery of data over a single physical link. It accepts packets from the Network Layer, encapsulates them into frames, and passes the frames to the Physical Layer for transmission. At the receiving node, it performs the reverse operation and delivers the recovered packet to the Network Layer.

Figure: The Data Link Layer provides a link-level transfer between two directly connected nodes. Routers and intermediate systems may terminate one link-layer frame and create another for the next link.

Main functions of the Data Link Layer

  1. Framing: Divides the continuous bit stream into identifiable units called frames by adding headers and trailers.
  2. Physical addressing: Uses link-layer addresses (such as MAC addresses in Ethernet) to identify source and destination interfaces on a local link.
  3. Flow control: Prevents a fast sender from overwhelming a slower receiver by regulating the rate or amount of outstanding data.
  4. Error control: Detects transmission errors and, in protocols that support it, uses acknowledgements and retransmissions or correction mechanisms to recover.
  5. Access control: Determines which station may use a shared communication medium when multiple devices contend for it.
  6. Link management: Establishes, maintains or terminates link-level operation as required by the technology.
Exam distinction: Error detection is not identical to error correction. A CRC can detect many error patterns, but the receiver normally requests retransmission or discards a corrupted frame; Hamming codes can add enough redundancy to correct certain bit errors.

2. Services Provided to the Network Layer

The Data Link Layer provides an interface through which the Network Layer can send packets across a link. In the classic layered description, three service types are commonly distinguished:

2.1 Unacknowledged connectionless service

  • No logical connection is established before sending frames.
  • The sender transmits frames independently; the receiver does not acknowledge each frame at the DLL level.
  • Lost or damaged frames are not recovered by this service itself.
  • It is suitable for links where the error rate is low or where higher layers handle recovery. Traditional Ethernet is a common example of a connectionless link service.

2.2 Acknowledged connectionless service

  • No connection setup is required, but each frame is individually acknowledged.
  • If an acknowledgement is not received within the required time, the sender may retransmit the frame.
  • It is useful on less reliable links where recovery is desirable without maintaining a long-lived logical connection.

2.3 Acknowledged connection-oriented service

  • A logical connection is established before data transfer.
  • Frames are numbered and delivered reliably and in order using acknowledgements, sequence numbers and retransmissions.
  • The connection is released after communication is complete.
  • It is useful when reliable, ordered delivery over the link is required.
Service Connection setup Acknowledgement Reliability at DLL
Unacknowledged connectionless No No No DLL recovery guarantee
Acknowledged connectionless No Per frame Recovery through acknowledgement/retransmission
Acknowledged connection-oriented Yes Yes Reliable, ordered link delivery

3. Framing

Definition: Framing is the process of dividing the bit stream received from the Network Layer into manageable data units called frames. The receiver must be able to identify where each frame begins and ends.

At the Physical Layer, bits may arrive as a continuous stream. The Data Link Layer adds framing information so the receiver can recognize boundaries, identify control information and check the frame for errors.

General frame format

A generic frame may contain addressing and control fields in its header, payload in the middle, and an error-detection field in its trailer. Exact fields depend on the protocol.

3.1 Character count

A field in the frame header specifies the number of characters (or bytes) present in the frame. The receiver reads the count and uses it to locate the end of the frame.

  1. The sender places the frame length in the count field.
  2. The receiver reads the count and collects the indicated number of bytes.
  3. It then treats the next byte as the beginning of the next frame.

Limitation: If the count field is corrupted, the receiver may lose synchronization and interpret subsequent frame boundaries incorrectly. A later valid count does not always restore synchronization immediately.

3.2 Byte stuffing (character stuffing)

In byte-oriented framing, special flag bytes mark the beginning and end of a frame. If the same flag byte appears in the payload, the sender inserts an escape byte before it. This process is called byte stuffing. The receiver removes the inserted escape byte before delivering the original data.

Advantage: Payload can contain any byte pattern without being mistaken for a frame delimiter. Limitation: Extra escape bytes increase the transmitted frame length when special bytes occur.

3.3 Bit stuffing

Bit-oriented protocols use a special flag bit pattern to mark frame boundaries. In HDLC, the flag is 01111110. To prevent this pattern from appearing inside the payload, the sender inserts a 0 after every sequence of five consecutive 1 bits in the data. The receiver removes each inserted zero after detecting five consecutive ones.

Advantages: It is independent of character encoding and supports arbitrary bit-oriented data. Limitation: The number of inserted bits varies with the data pattern.

3.4 Physical-layer coding violations

Some physical encodings have signal patterns that are not used for ordinary data. A reserved or invalid signal pattern can therefore be used to mark frame boundaries. This method avoids adding stuffing bits, but it is possible only when the physical encoding provides suitable unused symbols.

Method Boundary identification Main limitation / consideration
Character count Length field in header Corrupted count can destroy synchronization.
Byte stuffing Special start/end bytes; escape special payload bytes Extra bytes are inserted when needed.
Bit stuffing Flag bit pattern; insert zero after five consecutive ones Variable bit overhead; sender and receiver must implement the rule.
Coding violations Reserved physical signal pattern Requires unused code symbols in the physical encoding.

Variable-length frames vs fixed-length frames

Fixed-length framing uses frames of a predetermined size, so boundaries can be inferred from position or fixed size. Variable-length framing permits the payload size to vary and uses a length field or delimiters/stuffing to identify boundaries.

Fixed-length frames Variable-length frames
All frames have the same defined size. Frame size can vary within protocol limits.
Boundary detection can be simple after synchronization. Needs a length field, delimiters or stuffing.
May waste space when data is smaller than the fixed payload capacity. Can use link capacity more efficiently for differently sized data units.
Simple buffering and processing can be possible. More flexible, but boundary handling is more involved.

4. Error Detection and Error Correction

During transmission, noise, interference, attenuation or other physical effects may change one or more bits. Error-control techniques add redundant information so that a receiver can detect or correct such changes.

Types of transmission errors

  • Single-bit error: Exactly one bit in a data unit changes from 0 to 1 or from 1 to 0.
  • Burst error: Two or more bits in a data unit are affected; the erroneous bits may be separated by correct bits. Burst length is measured from the first corrupted bit to the last corrupted bit.

Detection and correction

Error detection

Redundant bits allow the receiver to determine that the received data is inconsistent with the code rules. The receiver may discard the frame or request retransmission.

Examples: parity, checksum and CRC.

Error correction

Redundant bits provide enough information for the receiver to identify and correct certain errors without asking for retransmission.

Example: Hamming code for single-bit correction.

A code's Hamming distance is the number of bit positions in which two codewords differ. If the minimum Hamming distance of a code is d, it can detect up to d − 1 bit errors and correct up to floor((d − 1)/2) bit errors.

5. Parity Bits

Parity bit: An extra bit appended to a group of data bits so that the total number of 1s follows an agreed parity rule.

Even parity

The parity bit is selected so that the total number of 1s in the data plus parity bit is even.

Odd parity

The parity bit is selected so that the total number of 1s in the data plus parity bit is odd.

Data bits Number of 1s Even parity bit Odd parity bit
1011001 4 0 1
1011011 5 1 0

Working

  1. The sender counts the number of 1s in the data bits.
  2. It calculates the parity bit according to the selected even or odd rule.
  3. The parity bit is transmitted with the data.
  4. The receiver counts the 1s again and checks whether the parity condition is satisfied.
  5. If the condition fails, an error is detected.

Advantages: Simple, inexpensive and easy to implement. Limitations: A single parity bit detects every odd number of bit flips, but it cannot detect an even number of bit flips. It does not identify the erroneous bit and cannot correct it by itself.

Two-dimensional parity

In two-dimensional parity, data bits are arranged in rows and columns. A parity bit is calculated for each row and each column. If a single bit changes, the incorrect row and incorrect column intersect, identifying the bit that can be corrected. Some multiple-bit error patterns may still escape detection or may not be uniquely correctable.

6. Checksum

Checksum: An error-detection value calculated from a data unit using arithmetic, appended to the data, and recomputed by the receiver to check whether the data may have been corrupted.

Sender-side procedure (one's-complement checksum)

  1. Divide the data into equal-sized words (commonly 16-bit words in Internet checksum use).
  2. Add all words using one's-complement addition. Any carry beyond the word width is wrapped around and added to the least significant end.
  3. Complement every bit of the final sum. This is the checksum.
  4. Transmit the data words along with the checksum.

Receiver-side procedure

  1. Add all received data words and the received checksum using the same one's-complement addition.
  2. If the result is all 1s (equivalently, its complement is zero), the check passes.
  3. Otherwise, an error is indicated.

Worked example (8-bit words for illustration)

Take two data words: 10011001 and 11100010.

  10011001
+ 11100010
-----------
1 01111011   (carry out = 1)
  01111011
+        1   (wrap the carry around)
-----------
  01111100   (sum)
  10000011   (one's complement = checksum)

The sender transmits 10011001 11100010 10000011. At the receiver, adding all three words with end-around carry produces 11111111 if no error is detected.

Advantages and limitations

  • Simple and efficient in software.
  • Detects many common errors in transmitted data.
  • It is not as strong as CRC for many burst-error patterns.
  • Different error patterns can produce the same checksum, so checksum verification is not proof that data is error-free.

7. Hamming Codes

Hamming code: A linear error-correcting code that inserts parity/check bits at selected positions so that the receiver can locate and correct a single-bit error.

Number of redundant bits

For m data bits and r check bits, the number of check bits must satisfy:

2r ≥ m + r + 1
The left side represents the possible syndrome values; the right side accounts for every data/check-bit position plus the no-error condition.

Positioning of check bits

Number bit positions starting from 1. Place check bits at positions that are powers of two: 1, 2, 4, 8, 16, .... Fill the remaining positions with data bits.

Position 1 2 3 4 5 6 7
Bit type P1 P2 D1 P4 D2 D3 D4

Parity coverage for the (7,4) Hamming code

  • P1 checks positions whose binary position number has its least significant bit set: 1, 3, 5 and 7.
  • P2 checks positions with the second binary bit set: 2, 3, 6 and 7.
  • P4 checks positions with the third binary bit set: 4, 5, 6 and 7.

Encoding and error correction procedure

  1. Choose the data bits and determine the required number of check bits using 2^r ≥ m+r+1.
  2. Insert check bits at power-of-two positions.
  3. For each check bit, calculate the selected even (or agreed) parity across its covered positions.
  4. Transmit the complete codeword.
  5. The receiver recalculates the parity checks. Their results form a binary syndrome.
  6. A zero syndrome indicates no single-bit error was identified. A non-zero syndrome gives the position number of the erroneous bit in a standard Hamming single-error-correcting code; flip that bit to correct it.
Scope note: Basic Hamming code provides single-error correction. A Hamming code with an additional overall parity bit is commonly called SECDED (single-error correction, double-error detection); the extra bit allows detection of a two-bit error, but not correction of it.

8. Cyclic Redundancy Check (CRC)

CRC: A powerful error-detection technique in which a bit sequence is treated as a polynomial over modulo-2 arithmetic and divided by a predetermined generator polynomial. The remainder is appended to the data.

Important properties

  • Modulo-2 addition and subtraction are both performed using XOR; there are no carries or borrows.
  • The generator is represented as a bit pattern and its highest- and lowest-order coefficients are normally 1.
  • If the generator has degree r, the sender appends r zero bits before division and ultimately appends an r-bit remainder.

CRC generation at sender

  1. Let the data bit sequence be D and the generator bit sequence be G.
  2. If the generator has degree r, append r zeros to the data.
  3. Divide the augmented data by the generator using modulo-2 division (XOR subtraction).
  4. Take the r-bit remainder and append it to the original data.
  5. Transmit the resulting codeword.

CRC checking at receiver

The receiver divides the complete received codeword by the same generator. A zero remainder means the check passes; a non-zero remainder indicates an error. A zero remainder does not guarantee that no error occurred, because some error patterns are undetectable by a particular generator.

Small worked example

Use data 1101 and generator 1011 (degree 3). Append three zeros: 1101000. Modulo-2 division by 1011 gives remainder 001. Therefore the transmitted codeword is 1101001. The receiver divides 1101001 by 1011; the remainder is 000.

How to perform modulo-2 division: Align the generator under the leftmost 1 of the current working bits and XOR it with that section. Bring down the next bit and repeat until fewer than the generator's number of bits remain. The final remainder is padded to exactly r bits.
Technique Core operation Primary capability Limitation
Parity Count 1s and add parity bit(s) Detects odd-number bit flips in a protected group Cannot detect every even-number error; no correction with one parity bit
Checksum One's-complement word addition Detects many data corruption patterns Some different error patterns can yield the same checksum
Hamming code Parity checks and syndrome Corrects a single-bit error in basic form Basic form does not reliably correct multiple-bit errors
CRC Modulo-2 polynomial division Strong detection of many random and burst errors Detection only; recovery is handled by a higher/reliability protocol

9. Flow Control Protocols

Flow control is a set of procedures that regulate the rate of data transmission so that a sender does not transmit more data than the receiver can accept and buffer. It is distinct from congestion control, which deals with overload within the network.

9.1 Unrestricted Simplex Protocol

This is a basic conceptual protocol for a noiseless channel where data flows only from sender to receiver and the receiver is assumed to be always ready. There is no need for flow control or error control.

  • Communication is simplex: data travels in one direction.
  • The sender continuously sends frames whenever it has data.
  • The channel is assumed error-free, and the receiver has enough capacity.
  • No acknowledgements, sequence numbers or retransmissions are required.

Limitation: It is an idealized protocol and does not model real links with finite receiver buffers or transmission errors.

9.2 Stop-and-Wait Protocol

In the basic Stop-and-Wait flow-control protocol, the sender transmits one frame and waits until the receiver is ready/acknowledges before sending the next frame. Only one frame can be outstanding at a time.

  1. The sender transmits one frame.
  2. The receiver accepts the frame and sends an acknowledgement (ACK).
  3. After receiving the ACK, the sender transmits the next frame.
  4. The cycle continues until all data is sent.

Advantages: Simple implementation, small buffer requirement and easy sequencing. Disadvantage: Link utilization can be low when propagation delay is large because the sender remains idle while waiting.

Stop-and-Wait ARQ (error-control extension)

When errors and lost frames are considered, Stop-and-Wait ARQ uses a timer, acknowledgements and sequence numbers (typically alternating 0 and 1). If a frame or ACK is lost or damaged, the sender retransmits after timeout. The receiver uses sequence numbers to recognize and discard duplicate retransmissions while acknowledging the expected frame.

9.3 Sliding Window Protocol

Sliding Window allows multiple frames to be sent before acknowledgements are received. The sender and receiver maintain windows that define which sequence-numbered frames may be transmitted or accepted. As acknowledgements arrive, the sender's window advances (“slides”), allowing additional frames to be sent.

Types of sliding-window ARQ

Go-Back-N ARQ

  • Sender can transmit several frames without waiting.
  • Receiver generally accepts frames in order and discards out-of-order frames.
  • If a frame is lost/damaged, the sender retransmits that frame and all later outstanding frames.
  • Uses cumulative acknowledgements in the common form.

Selective Repeat ARQ

  • Receiver can buffer correctly received out-of-order frames.
  • Only lost or damaged frames need retransmission.
  • Uses individual/selective acknowledgements and a retransmission timer per outstanding frame (conceptually).
  • Requires more receiver buffering and more complex logic.
Basis Stop-and-Wait Go-Back-N Selective Repeat
Frames in flight One Multiple Multiple
Receiver handling One frame at a time Normally accepts in-order frames only Can buffer out-of-order frames
Retransmission One unacknowledged frame Lost/damaged frame and following outstanding frames Only missing/damaged frames
Complexity Low Moderate Higher
Efficiency on noisy links Can be low Can waste bandwidth by repeating later frames Often better when errors are isolated, at added complexity

10. Point-to-Point Protocol (PPP)

PPP is a data-link protocol used to carry network-layer packets over point-to-point links. It provides framing, link configuration and support for multiple Network Layer protocols.

Main functions / features

  • Encapsulates Network Layer packets over point-to-point links.
  • Provides framing and an error-detection field (Frame Check Sequence).
  • Uses the Link Control Protocol (LCP) to establish, configure, test and terminate the data-link connection.
  • Uses Network Control Protocols (NCPs) to configure network-layer protocols.
  • Supports authentication options such as PAP and CHAP where configured.
  • PPP detects errors but does not itself provide general retransmission-based error correction in its normal operation.

PPP frame format

Traditional PPP frame fields: Flag, Address, Control, Protocol, Information/Payload, FCS and closing Flag. Address and Control values are commonly fixed in the basic format; field compression may be negotiated.

PPP operation phases

  1. Link establishment: LCP negotiates link parameters and options.
  2. Optional authentication: The peers may authenticate using PAP or CHAP.
  3. Network-layer configuration: NCP configures the selected Network Layer protocol.
  4. Data transfer: Network-layer packets are encapsulated and exchanged.
  5. Link termination: LCP closes the link.

11. High-Level Data Link Control (HDLC)

HDLC is a bit-oriented, synchronous data-link protocol that provides framing and link management, and supports flow and error control using sequence numbers and acknowledgements in its numbered modes.

Features

  • Bit-oriented protocol; it is not restricted to character boundaries.
  • Uses the flag 01111110 at the beginning and end of a frame.
  • Uses bit stuffing to prevent a flag pattern from occurring in the frame body.
  • Uses a Frame Check Sequence (FCS), generally based on CRC, for error detection.
  • Supports point-to-point and multipoint configurations in its protocol model.
  • Provides data transfer and link-management control frames.

HDLC frame format

HDLC frame types

Frame type Purpose Typical use
Information (I-frame) Carries user data and sequence/acknowledgement information. Data transfer with sequencing and flow/error control.
Supervisory (S-frame) Provides flow and error-control functions without carrying user data. Receive Ready (RR), Receive Not Ready (RNR), Reject (REJ), Selective Reject (SREJ).
Unnumbered (U-frame) Provides link-management and certain unnumbered data functions. Link setup, disconnection and mode management.

HDLC operation

  1. Flags delimit frames and establish synchronization.
  2. The Address field identifies the secondary station or destination in the link configuration.
  3. The Control field identifies I, S or U frame format and carries sequence/control information.
  4. The Information field carries user data when present.
  5. The FCS allows the receiver to detect transmission errors.
  6. Bit stuffing is applied to the frame contents between the flags; the receiver destuffs the bit stream.

PPP vs HDLC

12. Pure ALOHA and Slotted ALOHA

ALOHA is a random-access medium access control technique in which stations transmit when they have frames to send. If transmissions collide, the affected station waits for a random time before attempting retransmission.

12.1 Pure ALOHA

  1. A station transmits whenever a frame is ready.
  2. The receiver returns an acknowledgement if the frame is received correctly.
  3. If the sender does not receive an acknowledgement within the timeout period, it assumes a collision or loss.
  4. The sender waits for a random backoff interval and retransmits.

In Pure ALOHA, a frame can collide with another frame that begins within one frame-time before or after its own start. The vulnerable period is therefore 2T, where T is the frame transmission time.

12.2 Slotted ALOHA

  1. Time is divided into equal slots, each one frame transmission time long.
  2. A station may begin transmission only at the start of a slot.
  3. If two or more stations transmit in the same slot, their frames collide.
  4. After a collision, each station waits a random number of slots before retransmission.

Because transmissions begin only at slot boundaries, the vulnerable period is reduced to T.

Basis Pure ALOHA Slotted ALOHA
Transmission start Any time Only at slot boundaries
Synchronization Not required Required
Vulnerable period 2T T
Maximum theoretical throughput 1/(2e) ≈ 0.184 (18.4%) 1/e ≈ 0.368 (36.8%)
Collision probability Higher for the same offered load Lower due to slot alignment
Implementation Simpler Needs slot timing synchronization

For the standard idealized model, throughput is S = G e−2G for Pure ALOHA and S = G e−G for Slotted ALOHA, where G is the average number of transmission attempts per frame time (including retransmissions). The maxima occur at G = 0.5 and G = 1 respectively.

13. CSMA, CSMA/CD and CSMA/CA

13.1 Carrier Sense Multiple Access (CSMA)

CSMA is a contention-based access method in which a station senses the communication channel before transmitting. It attempts to reduce collisions by checking whether the medium is busy or idle.
  1. A station with a frame to send listens to the channel.
  2. If the channel is idle, it transmits according to the selected CSMA persistence rule.
  3. If the channel is busy, it defers transmission or waits according to the rule.
  4. Collisions can still occur because propagation delay means two stations may both sense an idle channel before either signal reaches the other.

Persistence methods

  • 1-persistent CSMA: A station transmits immediately when the channel becomes idle. If busy, it continuously senses the channel. This can lead to collisions when multiple stations are waiting.
  • Non-persistent CSMA: If the channel is busy, a station waits a random time before sensing again. This can reduce collisions but may increase delay.
  • p-persistent CSMA: Used with slotted channels. When the channel is idle, the station transmits in a slot with probability p and defers to the next slot with probability 1−p.

13.2 CSMA with Collision Detection (CSMA/CD)

CSMA/CD was used in shared, half-duplex Ethernet. A station senses the medium, transmits if idle, and continues monitoring while transmitting so it can detect a collision.

  1. Carrier sense: Listen to determine whether the medium is idle.
  2. Transmit: If idle, begin sending the frame.
  3. Collision detection: Monitor the medium during transmission.
  4. Jam signal: If a collision is detected, stop normal transmission and send a jam signal so other stations become aware of the collision.
  5. Binary exponential backoff: Wait for a random number of slot times before retrying. The backoff range grows after repeated collisions, subject to the Ethernet algorithm's limit.
  6. Retry: Sense the medium and attempt transmission again.

Modern Ethernet note: Full-duplex switched Ethernet links do not use CSMA/CD because each link is point-to-point and collisions do not occur in normal full-duplex operation. CSMA/CD is important for understanding traditional shared Ethernet.

13.3 CSMA with Collision Avoidance (CSMA/CA)

CSMA/CA is used by IEEE 802.11 wireless LANs. A wireless station cannot reliably detect a collision while transmitting in the same way as a wired Ethernet station, so the protocol attempts to reduce the chance of collisions before transmission.

  1. Carrier sensing: The station checks whether the wireless medium is idle.
  2. Interframe waiting: It waits for the required interframe space.
  3. Random backoff: It selects a random backoff counter from the contention window and decrements it while the channel remains idle.
  4. Transmission: When the counter reaches zero, the station transmits.
  5. ACK: The receiver sends an acknowledgement after successful reception.
  6. Retry: If the sender does not receive the ACK, it assumes a collision or loss, increases the contention window according to the procedure and retries.

RTS/CTS mechanism

IEEE 802.11 may use Request to Send (RTS) and Clear to Send (CTS) control frames to reserve the medium before sending a long data frame. A station sends RTS; the access point/receiver responds with CTS; other stations hearing these frames defer for the indicated duration. This can reduce collisions caused by hidden stations, although it adds control-frame overhead.

14. Introduction to IEEE Standards: IEEE 802.3 and IEEE 802.11

IEEE 802 family

The IEEE 802 family defines standards for local and metropolitan area network technologies, including both Physical Layer and Data Link Layer specifications. The Data Link Layer is commonly described as having Logical Link Control (LLC) and Media Access Control (MAC) sublayers.

14.1 IEEE 802.3 — Ethernet

IEEE 802.3 specifies Ethernet. It defines Ethernet MAC operation and Physical Layer specifications for wired LANs. Ethernet frames include destination and source MAC addresses, a length/type field, payload and a Frame Check Sequence (FCS).

  • Used for wired local area networking.
  • Uses MAC addresses for local frame delivery.
  • Modern Ethernet commonly uses switches and full-duplex point-to-point links.
  • Older shared half-duplex Ethernet used CSMA/CD.
  • Ethernet PHY variants define different media and speeds, such as twisted pair and optical fibre.

14.2 IEEE 802.11 — Wireless LAN (Wi-Fi)

IEEE 802.11 specifies wireless local area network operation. It defines MAC procedures and multiple radio Physical Layer technologies for wireless communication in unlicensed and, depending on the band and jurisdiction, other designated spectrum.

  • Provides wireless connectivity between stations and access points, or in supported peer modes.
  • Uses CSMA/CA-based channel access rather than classic collision detection.
  • Supports association, authentication and wireless frame exchange procedures.
  • Radio propagation, interference, obstacles and shared airtime affect performance.
  • Security mechanisms are defined and updated across 802.11 generations; deployment should use modern supported security settings.

Reference textbooks

Andrew S. Tanenbaum and David J. Wetherall, Computer Networks, 5th Edition, Pearson.

Chapter 3, The Data Link Layer: framing (Section 3.1.2), error detection and correction (Section 3.2), elementary data-link protocols (Section 3.3), sliding-window protocols (Section 3.4), and example data-link protocols including PPP (Section 3.5). Chapter 4, The Medium Access Control Sublayer: ALOHA and multiple-access protocols (Section 4.2).

Behrouz A. Forouzan, Data Communications and Networking, 5th Edition, McGraw-Hill.

Use the Data Link Control and Media Access Control chapters for framing, error/flow control, PPP/HDLC and random-access protocols. Page numbers vary by printing; chapter/section headings are safer locators.

Numerical practice checklist

  • Generate even and odd parity bits and test received words.
  • Compute and verify a one's-complement checksum, including end-around carry.
  • Determine the number and positions of Hamming check bits, calculate the syndrome and correct a single-bit error.
  • Perform modulo-2 division to generate and verify a CRC remainder.
  • Explain the CSMA/CD collision process and binary exponential backoff; distinguish it from CSMA/CA.
Exam-writing structure: For a 7–8 mark answer, begin with a definition, explain the working in ordered steps, add a labelled diagram or frame format where relevant, include advantages/limitations or a comparison table, and finish with a brief application or conclusion.
