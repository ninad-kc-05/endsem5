1. Application Layer: Role and Services

Definition

The Application Layer is the top layer of the TCP/IP model. It provides network services to application programs and acts as the interface between user-facing software and the network. It enables applications on different hosts to communicate using agreed application protocols.

In the OSI reference model, application, presentation and session functions are represented as separate layers. In the TCP/IP model, these higher-level functions are commonly grouped within the Application Layer.

Major functions

  1. Providing network services: Makes services such as web access, file transfer, remote login, name resolution and email available to applications.
  2. Defining communication rules: Specifies message formats, commands, responses and the order in which messages are exchanged.
  3. Identifying communication partners: Uses names, addresses and service identifiers to locate the required remote service.
  4. Data representation at application level: Defines how application information is structured and interpreted by communicating programs.
  5. Supporting distributed applications: Enables programs running on different devices to exchange information over a network.

Conceptual view: an application protocol governs the exchange between application processes.

2. Application-Layer Paradigms

An application-layer paradigm describes the general arrangement and interaction pattern used by networked applications. Two important paradigms are Client-Server and Peer-to-Peer.

A. Client-Server Paradigm

Definition: In the Client-Server paradigm, a server is a program that provides a service, and a client is a program that requests and uses that service. The client initiates communication with the server, which listens for requests and sends responses.

Working

  1. The server program starts and waits for requests at a known network endpoint.
  2. A client program obtains the server's address and establishes communication.
  3. The client sends a request describing the required service or resource.
  4. The server processes the request and sends a response.
  5. The client receives and presents or processes the response.

Basic client-server request and response sequence.

Characteristics

  • Central service provider: The server provides a defined service or shared resource.
  • Request-response interaction: Clients request services and servers respond.
  • Known server endpoint: Clients need a way to locate the server, commonly using a host name or IP address and a port.
  • Concurrent clients: A server may handle requests from multiple clients, depending on its implementation and capacity.
  • Administration: Server resources, software and access policies can be managed centrally.

Advantages

  • Centralized management of data and services.
  • Consistent access control, backup and maintenance can be applied at the server.
  • Resources can be shared by many clients.
  • Clients can be relatively simple because service logic may reside on the server.

Limitations

  • A server failure can make the service unavailable unless redundancy is provided.
  • The server may become a performance bottleneck when requests increase.
  • Server infrastructure and administration can add cost.
  • Centralized services require suitable security and availability measures.

B. Peer-to-Peer (P2P) Paradigm

Definition: In a Peer-to-Peer paradigm, participating computers (peers) can act as both clients and servers. A peer can request resources from other peers and also provide resources to them.

Characteristics

  • Resources and services may be distributed among participating peers.
  • Peers can communicate directly, depending on the P2P system design.
  • There may be no single central server responsible for all data transfer.
  • Peers can join or leave, so the set of available resources may change dynamically.

Advantages and limitations

Advantages

  • Work and resource sharing can be distributed.
  • Can scale by adding participating peers.
  • May avoid dependence on one central data-serving machine.

Limitations

  • Security and trust management can be difficult.
  • Availability depends on participating peers.
  • Management, discovery and consistency can be complex.

Client-Server vs Peer-to-Peer

Basis Client-Server Peer-to-Peer
Architecture Uses designated servers to provide services to clients. Peers can both request and provide services.
Control Often centrally administered. Often distributed among peers.
Resource location Resources are commonly maintained on servers. Resources may be distributed across peers.
Failure impact A critical server failure may interrupt the service. Failure of one peer may affect only resources or connections involving that peer, depending on design.
Examples Web browsing, email service, centralized file service. Peer-based file sharing and distributed collaboration systems.

3. Application Programming Interface (API)

Definition: An Application Programming Interface (API) is a defined set of rules, operations and interfaces through which one software component can request services or data from another software component. In network applications, APIs allow application programs to use communication services without implementing every lower-level networking detail themselves.

Role of an API in network applications

  1. The application calls an API operation to request a service, such as opening a connection or sending data.
  2. The API provides a defined interface and accepts the required parameters.
  3. The operating system or supporting library performs the underlying operation.
  4. The API returns a result, status or error information to the application.

Common characteristics

  • Abstraction: Hides many implementation details behind a simpler interface.
  • Defined operations: Specifies available functions, parameters, return values and error behaviour.
  • Reusability: Allows multiple programs to use the same service interface.
  • Interoperability: A documented API enables independently developed components to work together when they follow the same contract.

API and application protocol are not the same

Application Programming Interface (API) Application Protocol
Interface used by software components or a program to request operations. Rules used by communicating applications to exchange messages over a network.
Defines callable operations, parameters and return values. Defines message formats, commands, responses and communication sequence.
Example: a socket API used by a program. Examples: HTTP, FTP and DNS.
A socket API is one way for an application to access transport-layer communication. HTTP, FTP and DNS are application-layer protocols that define communication between applications.

4. World Wide Web (WWW)

Definition: The World Wide Web (WWW) is a distributed information system in which resources such as web pages and other content are identified by Uniform Resource Locators (URLs) and accessed using web protocols, principally HTTP or HTTPS.

Main components

  • Web browser: Client software used to request, receive and display web resources.
  • Web server: Software that receives web requests and returns requested resources or generated responses.
  • Web resources: Documents, images, scripts, media and other content made available over the web.
  • URL (Uniform Resource Locator): Identifies the location and access method for a resource.
  • HTTP/HTTPS: Application protocols used for web communication. HTTPS is HTTP protected by TLS.
  • DNS: Commonly resolves the domain name in a URL to an IP address needed to contact the destination host.

Working of the WWW

  1. The user enters a URL or selects a link in the browser.
  2. The browser determines the destination host name and uses DNS resolution when necessary.
  3. The browser establishes a connection to the web server (with TLS for HTTPS).
  4. The browser sends an HTTP request for the required resource.
  5. The web server processes the request and returns an HTTP response.
  6. The browser interprets the response and displays the content. It may request additional resources such as images, stylesheets and scripts.

A browser commonly resolves a host name before exchanging HTTP messages with the web server.

5. Hypertext Transfer Protocol (HTTP)

Definition: HTTP is an application-layer protocol used for transferring web resources between clients and servers. It follows a request-response model: a client sends an HTTP request and the server returns an HTTP response.

Characteristics of HTTP

  • Client-server protocol: A client (such as a browser) sends requests to a server.
  • Request-response: The server responds to each request with a status and, where appropriate, representation data.
  • Stateless semantics: Each request is understood independently at the protocol level. Applications can maintain state using mechanisms such as cookies and server-side sessions.
  • Media independent: HTTP can transfer different kinds of content, identified using media types such as text/html or image/png.
  • Extensible: Headers allow clients and servers to exchange additional information.
  • Persistent connections: Modern HTTP versions can reuse connections to reduce connection overhead; exact connection handling depends on the HTTP version and transport.

HTTP request message

An HTTP/1.1 request has a request line, header fields, a blank line and an optional message body.

GET /index.html HTTP/1.1
Host: www.example.com
Accept: text/html
User-Agent: ExampleBrowser/1.0
Part Meaning
Request method Indicates the requested operation, such as GET or POST.
Request target Identifies the resource or target of the request.
HTTP version Indicates the HTTP version used in the message.
Headers Provide metadata such as host, accepted media types and authentication information.
Message body Optional data sent with methods such as POST or PUT.

Common HTTP methods

Method Purpose
GET Requests a representation of a resource.
HEAD Requests response headers corresponding to GET, without the response content.
POST Submits data for processing or resource-specific handling.
PUT Creates or replaces the state of the target resource with the supplied representation, according to server semantics.
DELETE Requests removal of the target resource's association or state.
OPTIONS Requests communication options for the target resource or server.
PATCH Requests a partial modification of a resource.

HTTP response message

An HTTP/1.1 response contains a status line, header fields, a blank line and an optional message body.

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 125

<html>...response content...</html>

Common HTTP status-code classes

Class Meaning Examples
1xx Informational: request received, continuing process. 100 Continue
2xx Success: request was successfully received, understood and accepted. 200 OK, 201 Created, 204 No Content
3xx Redirection: further action is needed to complete the request. 301 Moved Permanently, 302 Found, 304 Not Modified
4xx Client error: request appears to be incorrect or cannot be fulfilled as sent. 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found
5xx Server error: server failed to fulfil an apparently valid request. 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable

HTTP and HTTPS

HTTP HTTPS
HTTP messages are not protected by TLS by default. HTTP is carried over a TLS-protected connection.
Does not itself provide confidentiality or server authentication. TLS can provide confidentiality, integrity and server authentication when correctly configured.
Common default port: TCP 80. Common default port: TCP 443.
HTTP is stateless at the protocol level; this does not mean that websites cannot remember users. Cookies, tokens and server-side sessions can maintain application state.

6. File Transfer Protocol (FTP)

Definition: FTP is an application-layer protocol used to transfer files between a client and a server over a TCP/IP network. It supports operations such as listing directories, uploading files and downloading files.

Characteristics

  • FTP uses a client-server architecture.
  • It uses TCP to provide reliable transport.
  • Traditional FTP uses a separate control connection and data connection.
  • The control connection carries commands and replies; the data connection carries file data or directory listings.
  • FTP supports user authentication and file/directory operations, subject to server permissions.

FTP connections and ports

Connection Typical port Purpose
Control connection TCP 21 Commands and server replies; normally remains established during the FTP session.
Data connection — active mode Server initiates from TCP 20 in the traditional active-mode arrangement Transfers file or directory data to/from the client.
Data connection — passive mode Server advertises a negotiated server-side port Client initiates the data connection, often making operation easier through NAT/firewalls.

Working of FTP

  1. The FTP client connects to the server's control port.
  2. The client may authenticate using a username and password, or use an allowed anonymous login.
  3. The client sends commands such as listing a directory, retrieving a file or storing a file.
  4. For data transfer, a separate data connection is established using active or passive mode.
  5. The file or directory data is transferred and the data connection is closed as appropriate.
  6. The client ends the session by closing the control connection.

Advantages and limitations

Advantages

  • Designed specifically for file transfer.
  • Supports directory listing and file management commands.
  • Reliable delivery is provided by TCP.

Limitations

  • Traditional FTP does not encrypt credentials or file contents.
  • Separate data connections can complicate firewall and NAT configuration.
  • Secure alternatives such as SFTP or FTPS are preferred when confidentiality is required.
Security note: FTP and FTPS are not the same. FTPS is FTP protected with TLS. SFTP is a different file-transfer protocol that operates over SSH.

7. TELNET

Definition: TELNET is an application-layer protocol that provides a text-oriented remote terminal or command-line session between a client and a remote host.

Characteristics

  • Uses a client-server model for remote terminal access.
  • Traditionally uses TCP port 23.
  • Allows a user to interact with a remote system as though using a terminal connected to that system.
  • Uses Network Virtual Terminal (NVT) concepts to provide a common representation of terminal data and control functions.
  • Negotiates certain terminal options between client and server.

Working

  1. The TELNET client establishes a TCP connection to the remote host.
  2. The client and server may negotiate terminal options.
  3. The user enters commands in the client terminal.
  4. Input is transmitted to the remote host, where the remote system processes it.
  5. Output from the remote system is sent back and displayed by the client.

Limitation and security

Traditional TELNET sends data, including login credentials, without encryption. A person able to observe the traffic may read the transmitted information. Therefore, TELNET is unsuitable for secure remote administration over untrusted networks. SSH is the secure alternative for remote login.

8. Secure Shell (SSH)

Definition: Secure Shell (SSH) is a protocol used to establish a secure remote login and command-execution session over an insecure network. It provides encrypted communication and supports server authentication and user authentication.

Characteristics

  • Encryption: Protects session data against passive reading while in transit.
  • Authentication: Verifies the server and authenticates the user, commonly using passwords or public-key authentication.
  • Integrity: Protects data against undetected modification in transit.
  • Remote command execution: Allows commands to be executed on a remote machine.
  • Tunnelling and forwarding: Can securely forward selected network connections.
  • File transfer support: SFTP and SCP provide file-transfer facilities associated with SSH.

Working of SSH (high-level)

  1. The SSH client connects to the SSH server, normally on TCP port 22.
  2. The client and server negotiate protocol parameters and establish shared cryptographic keys.
  3. The client verifies the server's host identity using the host key and its trust information.
  4. The user authenticates to the server, for example with a password or public key.
  5. An encrypted session is established for terminal interaction, commands or supported forwarding.

Advantages

  • Protects remote-login credentials and session content through encryption.
  • Provides mechanisms for server and user authentication.
  • Supports secure remote administration over untrusted networks.
  • Can support secure tunnelling and file transfer.

TELNET vs SSH

Basis TELNET SSH
Purpose Remote terminal access. Secure remote login, command execution and tunnelling.
Default TCP port 23 22
Encryption Traditional TELNET does not encrypt session data. Encrypts the session after secure connection setup.
Authentication protection Credentials can be exposed on the network. Supports protected authentication methods.
Use today Limited to controlled labs or legacy environments. Commonly used for secure remote administration.

9. Domain Name System (DNS)

Definition: The Domain Name System (DNS) is a distributed, hierarchical naming system that translates human-readable domain names into information such as IP addresses. It allows users and applications to use names instead of remembering numerical IP addresses.

Why DNS is required

Network communication uses IP addresses to identify hosts, but names such as www.example.com are easier for people to remember and use. DNS provides a scalable mechanism for mapping domain names to resource records, including address records.

DNS hierarchy

  • Root domain: The top of the DNS hierarchy, represented by a dot.
  • Top-Level Domain (TLD): The next level, such as .com, .org, .in or .edu.
  • Second-level domain: The registered name under a TLD, such as example in example.com.
  • Subdomain/host label: A label to the left of the domain, such as www in www.example.com.

DNS components

Component Function
Stub resolver Client-side component that sends a DNS query on behalf of an application.
Recursive resolver Finds the requested DNS information on behalf of the client, using cache and queries to other DNS servers as needed.
Root name server Directs the resolver toward the appropriate TLD name servers.
TLD name server Directs the resolver toward authoritative servers for a domain under that TLD.
Authoritative name server Provides DNS records for the domain zone for which it is authoritative.

DNS name-resolution process

  1. An application asks the local resolver to resolve a domain name.
  2. The resolver checks its cache. If a valid cached answer exists, it can return it.
  3. If required, the recursive resolver queries DNS hierarchy servers, beginning with a root server.
  4. The root server refers the resolver to the relevant TLD name servers.
  5. The TLD server refers the resolver to the domain's authoritative name server.
  6. The authoritative server returns the requested record, such as an IPv4 or IPv6 address.
  7. The resolver returns the answer to the client and may cache it for the record's Time to Live (TTL).

Common DNS resource-record types

Record Purpose Example / description
A Maps a host name to an IPv4 address. www.example.com → 192.0.2.10
AAAA Maps a host name to an IPv6 address. Stores a 128-bit IPv6 address.
CNAME Creates an alias from one name to another canonical name. www → webserver.example.com
MX Identifies mail-exchange servers for a domain. Used to route email for a domain.
NS Identifies authoritative name servers for a zone. Lists the zone's name servers.
PTR Used for reverse DNS lookup from an address to a name. Commonly used in reverse-mapping zones.
TXT Stores text associated with a domain. Often used for domain verification and email policy data.

DNS transport and port

  • DNS commonly uses UDP port 53 for ordinary queries and responses.
  • DNS also uses TCP port 53, including for zone transfers and cases where TCP is required.
  • DNS caching reduces lookup delay and traffic. Cached records are normally retained according to their TTL.

Advantages of DNS

  • Users can access network services using memorable names.
  • Its hierarchical and distributed structure supports large-scale naming.
  • Caching improves response time and reduces repeated queries.
  • Multiple record types support different services, not only address mapping.

10. Self-Learning Topics

The following topics are explicitly listed as self-learning topics in the official syllabus. They are included here as supporting study notes, not as replacements for the main Module V syllabus.

A. Secure File Transfer Protocol (SFTP)

SFTP is the SSH File Transfer Protocol. It provides file access, transfer and management operations over an SSH connection. It is not simply FTP with encryption; it is a separate protocol with its own message operations.
  • Uses SSH for a protected communication channel.
  • Commonly uses TCP port 22 through the SSH service.
  • Supports file upload, download, directory listing and file operations, depending on server permissions.
  • Protects transferred data and authentication exchanges through the SSH connection.

B. Secure Copy Protocol (SCP)

SCP is a command-line method historically used to copy files between hosts over SSH. It uses SSH to protect the connection and authenticate the remote endpoint.
  • Used to copy files to or from a remote system.
  • Typically uses the SSH service on TCP port 22.
  • Provides encrypted transfer through SSH.
  • Modern implementations may use SFTP internally for compatibility; exact behaviour depends on the SSH implementation.

C. Simple Mail Transfer Protocol (SMTP)

SMTP is an application-layer protocol used to send and relay email between mail clients and mail servers, and between mail servers.
  • Follows a client-server command and response model.
  • Used for outgoing email submission and server-to-server mail transfer.
  • Common ports: TCP 25 for server-to-server transfer; TCP 587 for message submission; TCP 465 is commonly used for message submission with implicit TLS.
  • SMTP sends email; it is not the usual protocol used by a recipient to retrieve stored mail.

D. Post Office Protocol version 3 (POP3)

POP3 is an application-layer protocol that allows an email client to retrieve messages from a mail server. Its traditional model downloads messages to the client, with server-copy behaviour depending on client settings.
  • Designed primarily for retrieving email from a mailbox.
  • Commonly uses TCP port 110; POP3 over implicit TLS commonly uses TCP port 995.
  • Offers a relatively simple mail-retrieval model.
  • Traditional POP3 is less suited than IMAP to synchronizing folders and message state across multiple devices.

E. Internet Message Access Protocol (IMAP)

IMAP is an application-layer protocol that allows an email client to access and manage messages stored on a mail server.
  • Messages are generally maintained on the server and synchronized with clients.
  • Supports server-side folders and message flags.
  • Allows users to access the same mailbox from multiple devices with synchronized state.
  • Commonly uses TCP port 143; IMAP over implicit TLS commonly uses TCP port 993.

SMTP vs POP3 vs IMAP

Protocol Main purpose Common ports
SMTP Sending and relaying outgoing email. 25, 587, 465 (submission/TLS usage varies)
POP3 Retrieving email from a server, commonly by downloading messages. 110, 995 (TLS)
IMAP Accessing and managing server-stored email with synchronization. 143, 993 (TLS)

Key points to remember

  • Application-layer paradigms describe how networked applications are organized and interact.
  • In Client-Server, the client requests a service and the server provides it. In P2P, peers can act as both clients and servers.
  • An API is a software interface; an application protocol defines network message exchange.
  • WWW uses URLs and web protocols such as HTTP/HTTPS.
  • HTTP follows a request-response model and is stateless at the protocol level.
  • FTP uses separate control and data connections in its traditional design.
  • TELNET is unencrypted; SSH provides secure remote access.
  • DNS is hierarchical and distributed; it resolves names and stores different resource-record types.
  • SMTP sends email; POP3 and IMAP retrieve/access email.
  • SFTP and SCP use SSH and should not be confused with traditional FTP.
