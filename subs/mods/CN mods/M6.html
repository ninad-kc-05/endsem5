1. Multiprotocol Label Switching (MPLS)

Definition: MPLS (Multiprotocol Label Switching) is a packet-forwarding technique that directs packets through a network using short labels rather than requiring every intermediate router to make a forwarding decision using the packet's full network-layer destination address.

Why MPLS is used

In ordinary IP forwarding, a router examines the destination IP address and consults its forwarding table to choose the next hop. MPLS adds a label-based forwarding mechanism. At the edge of an MPLS network, packets are classified and assigned labels. Core routers then use those labels to forward packets along a pre-established label-switched path.

Important MPLS terms

TermMeaning
LabelA short identifier carried with a packet. It is used by MPLS routers to select the next forwarding action.
FEC — Forwarding Equivalence ClassA group of packets that are forwarded in the same way, for example along the same path and with similar forwarding treatment.
LER — Label Edge RouterAn edge router that adds an MPLS label when traffic enters the MPLS domain and removes the label when traffic leaves.
LSR — Label Switching RouterA router inside the MPLS domain that forwards packets based on their labels.
LSP — Label Switched PathThe sequence of MPLS routers followed by packets carrying a particular label or label-switched forwarding state.
Label stackOne or more MPLS labels carried together. Multiple labels can support hierarchical forwarding or services such as VPNs.

Simplified MPLS path. The exact label operations depend on the MPLS forwarding configuration.

2. MPLS Header Structure

An MPLS label stack entry is commonly called the MPLS shim header. It is 32 bits (4 bytes) long and is placed between the data-link header and the encapsulated network-layer packet in the common Ethernet/MPLS arrangement.

MPLS shim-header fields and widths.

FieldSizeFunction
Label20 bitsIdentifies the forwarding label used by the receiving MPLS router.
Traffic Class (TC)3 bitsUsed for traffic-class marking and quality-of-service treatment. Older descriptions may call this the EXP field.
Bottom of Stack (S)1 bitIndicates whether this is the last (bottom) label in the label stack. A value of 1 marks the bottom entry.
Time to Live (TTL)8 bitsLimits packet lifetime and helps prevent packets from circulating indefinitely.
Remember: 20 + 3 + 1 + 8 = 32 bits. The label is the largest field. The S bit identifies the bottom of a label stack; it is not a general packet-start flag.

3. Working of MPLS

  1. Packet enters the MPLS domain: The ingress Label Edge Router (LER) receives an IP packet.
  2. Classification: The ingress router determines the packet's Forwarding Equivalence Class (FEC).
  3. Label imposition: The ingress router attaches the appropriate MPLS label (or label stack) to the packet.
  4. Label switching: Each Label Switching Router (LSR) examines the incoming label, consults its label-forwarding information and forwards the packet. It commonly replaces the incoming label with an outgoing label; this is called label swapping.
  5. Label removal: At the egress edge, the MPLS label is removed and the packet is forwarded toward its destination using the appropriate network-layer forwarding process.
IP packet → Ingress LER (push label) → Core LSRs (swap label) → Egress LER (pop label) → Destination

Label operations

OperationMeaningUsually performed by
PushAdds a label to the packet or label stack.Ingress LER; may also occur within a network for nested label stacks.
SwapReplaces the top label with another label and forwards the packet.Transit LSR.
PopRemoves the top label from the label stack.Egress LER or a penultimate-hop router, depending on configuration.
Important clarification: MPLS is often described as operating between Layer 2 and Layer 3, sometimes called “Layer 2.5”. This is an informal teaching description, not a separate layer in the OSI reference model. MPLS can carry multiple network-layer protocols and is not limited to IPv4.

4. Advantages and Disadvantages of MPLS

Advantages

  • Efficient forwarding: Core routers can use compact labels to make forwarding decisions.
  • Traffic engineering: Traffic can be directed along selected paths rather than relying only on ordinary destination-based routing.
  • QoS support: Traffic classes can receive different forwarding treatment.
  • VPN support: MPLS can support provider-managed Layer 3 and Layer 2 VPN services.
  • Protocol flexibility: It can transport different kinds of network-layer traffic.
  • Scalable service delivery: Providers can build multiple logical services over a shared MPLS infrastructure.

Disadvantages

  • Complexity: Label distribution, path management and troubleshooting require specialized knowledge.
  • Cost: Deployment and operation can be expensive, particularly for smaller networks.
  • Provider dependence: A managed MPLS service may create dependence on the service provider's network and policies.
  • Configuration risk: Incorrect label or routing configuration can disrupt traffic.
  • Not encryption: MPLS VPN separation does not, by itself, encrypt the traffic payload.

5. 5G Radio-Spectrum Landscape and Requirements

Radio spectrum is the range of electromagnetic frequencies used for wireless communication. Mobile networks use assigned or otherwise authorized frequency bands to transmit signals between user devices and cellular base stations.

Why spectrum matters in 5G

5G is designed to support a mix of services, including high data rates, large numbers of connected devices, and applications that require responsive and reliable connectivity. No single frequency range is ideal for every requirement. 5G networks therefore use a range of spectrum bands and combine them with radio technologies and network deployment choices.

Broad spectrum ranges

Range (general description)Typical strengthsTypical limitationsCommon role
Low-bandWide-area coverage; generally better propagation and indoor reach.Limited bandwidth may constrain peak capacity.Broad coverage, rural areas and improved reach indoors.
Mid-bandBalances coverage and capacity; can provide substantial bandwidth.Coverage and building penetration are generally less extensive than lower bands.Important capacity layer in many 5G deployments.
High-band / mmWaveCan provide very wide bandwidth and very high peak data rates.Shorter range and greater sensitivity to obstacles; dense deployments may be needed.High-capacity hotspots, venues and selected dense urban locations.

These are broad engineering tendencies, not fixed guarantees. Actual coverage and performance depend on frequency, bandwidth, transmit power, antenna design, terrain, buildings, interference and network deployment.

5G spectrum requirements

  • High capacity: Enough spectrum and efficient use of it to support high traffic demand.
  • Wide coverage: Coverage across urban, suburban and rural environments.
  • Low latency: Radio and network design that can support responsive services.
  • Reliability: Consistent communication under expected operating conditions.
  • Massive connectivity: Support for large numbers of mobile and machine-type devices.
  • Mobility: Continuity as users move between cells and frequency layers.
  • Coexistence: Management of interference and compatibility with other spectrum users and services.
  • Efficient utilization: Flexible allocation and sharing where permitted by regulation.

6. Spectrum Access Modes and Sharing Scenarios

Spectrum access describes the regulatory and technical arrangement under which operators or services are allowed to use a frequency band. The exact licensing model varies by country and by frequency band.

Common spectrum access modes

Access modeDescriptionKey point
Licensed / exclusive accessA license grants an operator defined rights to use specified spectrum under stated conditions.Provides predictable access and regulatory protection, subject to license terms.
Shared licensed accessMultiple eligible users or operators share a band under coordinated rules or priority arrangements.Sharing rules help manage interference and access priority.
Unlicensed accessDevices may use a designated band without an individual exclusive spectrum license, provided they follow technical rules.Access is generally shared and interference cannot be excluded.

Spectrum-sharing scenarios

  • Static sharing: Spectrum portions are divided in advance among users, operators or services.
  • Dynamic sharing: Access to spectrum changes according to demand, availability, policy or coordination decisions.
  • Geographical sharing: Different users may use the same frequencies in different locations when interference conditions and rules allow it.
  • Time-based sharing: Users access the same spectrum at different times or according to scheduled access.
  • Priority-based sharing: A higher-priority user may receive access before a lower-priority user, according to the sharing framework.
  • Coexistence with existing services: 5G systems may need to operate while protecting incumbent or adjacent-band services from harmful interference.
Do not treat “licensed”, “shared” and “unlicensed” as radio technologies. They are spectrum access or authorization arrangements. Technologies such as beamforming and massive MIMO are ways to use radio resources more effectively.

7. 5G Spectrum Technologies

A. Massive MIMO

Massive MIMO (Multiple-Input Multiple-Output) uses a large number of antenna elements at a base station to communicate with multiple users and improve spectral efficiency and capacity. The system can use spatial processing to separate users or improve signal quality.

B. Beamforming

Beamforming uses antenna-array processing to focus radio energy in a chosen direction or toward a user rather than transmitting equally in all directions. It can improve signal strength and help manage interference, especially at higher frequencies.

C. Small cells and dense deployment

Small cells are low-power cellular access points used to add coverage or capacity in targeted areas. Deploying more cells can increase spatial reuse of spectrum, but requires careful planning, backhaul and interference coordination.

D. Carrier aggregation

Carrier aggregation combines multiple component carriers so that a device can use a wider effective bandwidth. The component carriers may be in the same band or different bands, depending on the supported configuration.

E. Dynamic Spectrum Sharing (DSS)

Dynamic Spectrum Sharing allows 4G LTE and 5G NR to use the same spectrum band through coordinated resource allocation. It can help operators introduce 5G without immediately refarming an entire band, although sharing introduces overhead and the benefit depends on traffic and implementation.

F. OFDM-based radio access

Orthogonal Frequency-Division Multiplexing (OFDM) divides a channel into many closely spaced orthogonal subcarriers. 5G NR uses OFDM-based waveforms, with flexible numerology to support different frequency ranges and deployment requirements.

8. 5G Architecture

A 5G system is commonly described using three broad parts: the User Equipment (UE), the 5G Radio Access Network (5G RAN), and the 5G Core (5GC). The radio access network connects devices over the air, while the core manages registration, mobility, sessions, policy and data forwarding.

9. Cybersecurity: Introduction and Need

Cybersecurity is the practice of protecting computers, networks, applications, devices and data from unauthorized access, misuse, disruption, modification or destruction.

Why cybersecurity is important

  • Confidentiality: Information should be accessible only to authorized people or systems.
  • Integrity: Data should remain accurate and should not be altered without authorization.
  • Availability: Systems and information should remain accessible when required.
  • Privacy: Personal and sensitive information should be collected, processed and shared appropriately.
  • Business continuity: Security controls help reduce downtime, financial loss and operational disruption.
  • Trust: Users need confidence that digital services and communications are dependable.

Common security objectives — CIA triad

The CIA triad is a foundational model for information security.

Basic cybersecurity measures

  • Use strong, unique passwords and multi-factor authentication.
  • Keep operating systems, applications and network devices updated.
  • Use firewalls, endpoint protection and secure network configurations.
  • Encrypt sensitive information in transit and at rest where appropriate.
  • Back up important data and test restoration procedures.
  • Limit user permissions according to the principle of least privilege.
  • Train users to recognize suspicious links, attachments and requests.
  • Monitor systems and prepare an incident-response process.

10. Cybercrime: Definition and Types

Definition: Cybercrime refers to unlawful activities in which computers, digital devices, networks or online services are used as tools, targets or environments for committing an offence.

A cybercrime may involve more than one category. For example, phishing can be used to steal credentials, which may then be used for unauthorized access or financial fraud.

11. Self-Learning: Cyber-Attacks, Vulnerabilities and Precautions

Cyber-attack vs vulnerability vs threat

TermMeaning
ThreatA potential cause of harm to a system, organization or user.
VulnerabilityA weakness in software, hardware, configuration, process or human behavior that could be exploited.
ExploitA method or code that takes advantage of a vulnerability.
Cyber-attackAn attempt to compromise confidentiality, integrity or availability, or to gain an unauthorized advantage.
RiskThe possibility and impact of harm when a threat exploits a vulnerability.

Common cyber-attacks

  • Malware: Malicious software such as viruses, worms, Trojans, spyware and ransomware.
  • Phishing and social engineering: Manipulating people into disclosing information or performing unsafe actions.
  • Password attacks: Attempts to guess, reuse, steal or otherwise compromise passwords.
  • Denial-of-Service: Making a service unavailable by exhausting its resources or network capacity.
  • Man-in-the-Middle (MitM): Intercepting or altering communication between parties, often when communication is not properly protected.
  • Injection attacks: Supplying malicious input that an application incorrectly treats as commands or queries.
  • Insider threats: Harm caused by a person with legitimate access, intentionally or accidentally.
  • Zero-day exploitation: Exploiting a vulnerability before an effective fix is available or widely deployed.

Common vulnerabilities

  • Outdated operating systems, applications and firmware.
  • Weak, reused or default passwords.
  • Unnecessary open ports and exposed services.
  • Incorrect access permissions or excessive privileges.
  • Unencrypted or poorly protected communication.
  • Misconfigured cloud storage, routers, servers or databases.
  • Unsafe application input handling and insecure software design.
  • Lack of backups, monitoring or security awareness.

Precautions and prevention

  1. Patch regularly: Apply security updates to operating systems, applications, firmware and network equipment.
  2. Use strong authentication: Use unique passwords, a password manager and multi-factor authentication.
  3. Back up data: Keep protected backups and periodically test recovery.
  4. Use defensive controls: Configure firewalls, endpoint protection, secure DNS and network segmentation as appropriate.
  5. Encrypt information: Protect sensitive data during transmission and storage.
  6. Apply least privilege: Give users and applications only the access they need.
  7. Be alert to social engineering: Verify unexpected requests, links, attachments and payment instructions.
  8. Secure Wi-Fi: Use modern Wi-Fi security, change default router credentials and update router firmware.
  9. Monitor and respond: Review logs, detect unusual activity and have a plan for reporting and responding to incidents.
  10. Dispose of data safely: Securely erase or destroy storage media before reuse or disposal.
Exam distinction: A vulnerability is a weakness; a threat is a possible source of harm; an attack is an attempt to cause harm or exploit a weakness; a precaution is a measure that reduces the likelihood or impact.
