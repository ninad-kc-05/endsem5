1. Introduction to the Network Layer

Definition

The Network Layer is Layer 3 of the OSI reference model. It is responsible for delivering packets from a source host to a destination host across one or more interconnected networks. It provides logical addressing and determines a route through intermediate routers. Unlike the Data Link Layer, which provides delivery over a single link, the Network Layer supports source-to-destination delivery across multiple links.

Main functions

  1. Logical addressing: Uses network-layer addresses such as IPv4 or IPv6 addresses to identify source and destination interfaces.
  2. Routing: Selects a suitable path through interconnected networks.
  3. Forwarding: Transfers a packet from an incoming interface to the selected outgoing interface using a forwarding table.
  4. Internetworking: Connects networks that may use different link technologies.
  5. Fragmentation / packet-size handling: Deals with differences in link maximum transmission units (MTUs). IPv4 routers may fragment packets when permitted; IPv6 routers do not fragment packets in transit.
  6. Error reporting and diagnostics: Supporting protocols such as ICMP report selected delivery and network conditions.
  7. Congestion and QoS support: Network mechanisms can manage traffic load and provide differentiated service characteristics.

Conceptual path: each router examines the destination network-layer address and forwards the packet toward the next hop.

Routing versus forwarding

Routing Forwarding
Determines the path or next hops through the network. Moves an arriving packet from an input interface to an output interface.
Uses routing algorithms and routing protocols. Uses the forwarding table / forwarding information base.
Usually a control-plane function. Per-packet data-plane function.
May respond to topology or metric changes. Performs the immediate forwarding decision.

2. Network Layer Protocols and Packet Delivery

The principal Internet Network Layer protocol is Internet Protocol (IP). IP provides connectionless, best-effort datagram delivery: it does not itself guarantee delivery, ordering, duplicate suppression or recovery from packet loss. Reliability, when required by an application, is provided by higher-layer protocols such as TCP.

Important protocols associated with the Network Layer

Protocol Purpose
IPv4 32-bit logical addressing and datagram delivery.
IPv6 128-bit addressing and updated IP packet format.
ICMP Error reporting and diagnostic messages; used by tools such as ping.
IGMP IPv4 multicast group membership management on local networks.
ARP Maps an IPv4 address to a link-layer address on a local IPv4 network; it operates between link and network-layer functions.
Routing protocols Exchange reachability and path information so routers can build routing information.

Connectionless datagram delivery

  1. The source host determines whether the destination is on its local subnet.
  2. If local, it sends the packet directly over the local link; otherwise it sends it to a configured next-hop router (commonly the default gateway).
  3. Each router examines the destination IP address and consults its forwarding table.
  4. The router selects the outgoing interface and next hop, then encapsulates the IP packet in a new link-layer frame for the next link.
  5. The destination host receives the packet and passes its payload to the appropriate upper-layer protocol.
Remember: The IP source and destination addresses normally remain end-to-end across the route, while the link-layer source and destination addresses change at each routed hop.

3. Routing Concepts

Basic terminology

  • Router: A device that connects IP networks and forwards packets between them.
  • Next hop: The next router or destination to which a packet is sent.
  • Route: Information describing how to reach a destination prefix.
  • Metric: A value used to compare candidate routes, such as hop count, cost, delay or bandwidth-related cost.
  • Convergence: The state reached after routers have updated their routing information following a topology or reachability change.
  • Default route: A route used when no more specific matching route exists; commonly written as 0.0.0.0/0 in IPv4 and ::/0 in IPv6.

Routing table

A routing table stores destination prefixes and the information needed to reach them. A typical entry can include destination network/prefix, next-hop address, outgoing interface, metric and route source. Routers generally use longest-prefix matching: among matching routes, the most specific (longest) prefix is selected.

Destination prefix Next hop Interface Meaning
192.168.10.0/24 Directly connected G0/0 Destination belongs to a directly connected network.
10.0.0.0/8 192.168.10.1 G0/0 Send matching packets to the next-hop router.
0.0.0.0/0 192.168.10.254 G0/0 Default route for otherwise unmatched IPv4 destinations.

Types of routing

  • Static routing: Routes are manually configured by an administrator.
  • Dynamic routing: Routers learn and update routes by exchanging information using routing protocols.

4. IPv4 Addressing and Datagram Header

IPv4 address

An IPv4 address is a 32-bit logical address, usually written in dotted-decimal notation as four 8-bit octets. Each octet ranges from 0 to 255. Example: 192.168.1.10. A prefix length identifies the network portion; for example, 192.168.1.10/24 means the first 24 bits are the network prefix.

Network and host portions

The subnet mask or prefix length separates the network portion from the host portion. For a prefix of /24, the mask is 255.255.255.0; the first 24 bits identify the network and the remaining 8 bits identify addresses within that subnet.

IPv4 datagram header format

Simplified field layout. The base IPv4 header is 20 bytes; options can extend it up to 60 bytes.

Field Purpose
Version Identifies IP version; value 4 for IPv4.
IHL Internet Header Length, measured in 32-bit words.
DSCP / ECN Traffic-classification and explicit congestion notification bits.
Total Length Total datagram length in bytes, including header and data.
Identification Identifies fragments belonging to the same original datagram.
Flags Controls and indicates fragmentation conditions.
Fragment Offset Indicates a fragment's position in the original datagram.
TTL Time To Live; decremented by routers to prevent indefinite circulation.
Protocol Identifies the encapsulated upper-layer protocol, e.g. TCP or UDP.
Header Checksum Error check for the IPv4 header only; recalculated when relevant header fields change.
Source / Destination 32-bit source and destination IPv4 addresses.
Options and Padding Optional control information and alignment.

IPv4 characteristics

  • 32-bit address space.
  • Connectionless, best-effort datagram service.
  • Supports unicast, broadcast and multicast addressing.
  • Variable header length because of optional fields.
  • Uses TTL to limit packet lifetime.

5. IPv6 Addressing and Header

Need for IPv6

IPv6 was developed primarily to address the limitations of IPv4 address availability and to provide an updated Internet Protocol. Its address length is 128 bits, creating a vastly larger address space. IPv6 also uses a simplified fixed base header and supports extension headers for optional information.

IPv6 address notation

An IPv6 address contains eight groups of four hexadecimal digits separated by colons. Example: 2001:0db8:0000:0000:0000:ff00:0042:8329. Leading zeros within a group may be omitted, and one consecutive run of zero groups may be compressed using :: (only once in an address): 2001:db8::ff00:42:8329.

IPv6 base header

The IPv6 base header has a fixed size of 40 bytes.

Field Purpose
Version Value 6.
Traffic Class Supports traffic classification and differentiated handling.
Flow Label Labels packets belonging to a flow for special handling where supported.
Payload Length Length of the payload following the fixed base header.
Next Header Identifies the next extension header or upper-layer protocol.
Hop Limit Decremented by each forwarding router; packet is discarded when it reaches zero.
Source / Destination 128-bit source and destination IPv6 addresses.

IPv4 versus IPv6

Basis IPv4 IPv6
Address length 32 bits 128 bits
Notation Dotted decimal Colon-separated hexadecimal
Base header Variable: 20–60 bytes Fixed: 40 bytes
Checksum Header checksum present No base-header checksum
Broadcast Supports broadcast No broadcast; multicast and anycast are used
Fragmentation Source and routers can fragment, subject to flags and rules Performed by source using Fragment extension header; routers do not fragment in transit
Address configuration Manual or DHCP commonly used Manual, SLAAC and DHCPv6 options

6. Subnetting

Definition and purpose

Subnetting is the process of dividing one IP network into multiple smaller logical networks by borrowing bits from the host portion and extending the network prefix. It improves address organization, supports network segmentation, reduces broadcast-domain size in IPv4 LAN design and allows more efficient allocation of address blocks.

Important formulas for IPv4

  • Number of subnets created by borrowing s bits: 2s.
  • Number of host bits remaining: h = 32 − new prefix length.
  • Traditional usable host addresses per ordinary subnet: 2h − 2 (network and directed broadcast addresses excluded; special cases such as /31 point-to-point links and /32 host routes are exceptions).
  • Block size in an octet: 256 − subnet-mask value in the relevant octet.

Subnetting procedure

  1. Write the given network address and original prefix.
  2. Determine the required number of subnets and/or hosts per subnet.
  3. Choose the number of borrowed bits s so that 2s is at least the required subnet count.
  4. Calculate the new prefix: original prefix + borrowed bits.
  5. Calculate remaining host bits and verify that the host capacity is sufficient.
  6. Write the subnet mask, block size, subnet network IDs, usable host ranges and broadcast addresses.
Exam caution: Do not select a prefix using only the subnet-count requirement. Check both requirements: enough subnets and enough usable hosts in every subnet.

Worked example: divide 192.168.1.0/24 into at least 6 subnets with at least 30 hosts each

We need 6 or more subnets. Borrow 3 bits because 23 = 8. The new prefix is /24 + 3 = /27. Five host bits remain, so each subnet has 25 − 2 = 30 usable host addresses. The subnet mask is 255.255.255.224; block size is 256 − 224 = 32.

7. Supernetting and CIDR

Definition

Supernetting combines multiple contiguous smaller network blocks into one larger address block by moving the prefix boundary to the left. It is also called route aggregation or summarization when used to represent multiple routes with one summary prefix. CIDR (Classless Inter-Domain Routing) uses variable-length prefixes rather than fixed class A, B and C network boundaries.

Conditions for aggregation

  1. The networks must be contiguous address blocks.
  2. The number of equal-sized blocks combined is generally a power of two.
  3. The first network must begin on the correct boundary for the aggregate prefix.
  4. The network addresses must share the required common leading bits.

Worked example

Combine 192.168.0.0/24 and 192.168.1.0/24. Two adjacent /24 networks share the first 23 bits, and the first block is correctly aligned. They can be summarized as 192.168.0.0/23, covering 192.168.0.0 through 192.168.1.255.

Subnetting Supernetting
Divides one larger network into smaller subnets. Combines contiguous smaller networks into a larger aggregate.
Prefix length increases. Prefix length decreases.
Creates more specific network prefixes. Creates a less-specific summary prefix.
Used for segmentation and address allocation. Used to reduce routing-table entries and advertise aggregated routes.

8. Static Routing Algorithms (Non-adaptive)

Static routing uses routes manually configured by a network administrator. The router does not automatically calculate a new path in response to topology changes using a dynamic routing protocol.

Characteristics

  • Routes are entered manually and remain until changed or removed.
  • Does not generate routing-protocol update traffic.
  • Provides predictable path selection and can be useful in small or stable networks.
  • Requires manual maintenance when network topology or addressing changes.
  • Does not automatically adapt to a failed link unless an alternative mechanism or configured backup route is available.

Advantages and disadvantages

Advantages

  • Simple for small networks.
  • Low control-plane overhead.
  • Administrator has direct control over the path.
  • Can improve predictability and reduce exposure to routing-update manipulation.

Disadvantages

  • Does not scale well to large changing networks.
  • Manual configuration is time-consuming.
  • Configuration errors can cause unreachable networks or loops.
  • Topology changes require administrator intervention.

9. Dynamic Routing Algorithms (Adaptive)

Dynamic routing allows routers to exchange routing information using routing protocols. Routers calculate routes and update their routing tables when network topology or reachability changes. The algorithm is called adaptive because route decisions can respond to changes in the network.

Characteristics

  • Routers exchange routing information with neighbours or other routers.
  • Routes are selected using protocol-specific metrics and rules.
  • Can adapt to link failures and topology changes.
  • Requires processing, memory and bandwidth for protocol operation.
  • Convergence time and stability depend on the protocol and network design.

Static versus dynamic routing

Basis Static routing Dynamic routing
Configuration Manually configured. Learned and updated through routing protocols.
Adaptability Does not automatically adapt to topology changes. Can adapt after routing information converges.
Overhead Little or no routing-protocol update overhead. Uses CPU, memory and bandwidth for protocol operation.
Scalability Suitable for small, stable or stub networks. Suitable for larger and changing networks.
Failure response Requires manual change or configured failover mechanism. Can select another route if one is available and convergence succeeds.
Administration Manual maintenance. Protocol configuration and monitoring.

10. Routing Algorithms

10.1 Distance Vector Routing

In Distance Vector Routing, each router maintains a vector of distances (costs) to destination networks and the next hop for each destination. Routers periodically or when triggered share routing information with their neighbours. A router updates its route using information received from a neighbour and the cost of reaching that neighbour.

The Bellman–Ford update relation is commonly expressed as:

Dx(y) = minv { c(x,v) + Dv(y) }
Here, Dx(y) is router x's current least cost to destination y; c(x,v) is the cost from x to neighbour v; and Dv(y) is neighbour v's advertised cost to y.

Working

  1. Every router initially knows the cost to directly connected neighbours.
  2. Each router sends its distance vector to its neighbours.
  3. On receiving a neighbour's vector, a router adds the cost of the link to that neighbour to each advertised destination cost.
  4. It compares the new calculated costs with its current entries and retains a lower-cost route.
  5. Updates continue until the routing information stabilizes (converges).

Advantages: conceptually simple and distributed. Limitations: may converge slowly and can suffer from routing loops and the count-to-infinity problem. Split horizon, route poisoning and hold-down techniques are used by some protocols to reduce these problems.

10.2 Link State Routing

In Link State Routing, each router discovers its neighbours and link costs, creates link-state information, and distributes that information through the routing domain. Each router builds a topology database and independently runs Dijkstra's shortest-path-first algorithm to calculate the shortest-path tree rooted at itself.

Working steps

  1. Neighbour discovery: Discover directly connected routers.
  2. Cost measurement: Determine the cost of each link according to the protocol's metric.
  3. Link-state advertisement: Create information describing the router's links and costs.
  4. Flooding: Reliably distribute link-state information throughout the routing area/domain.
  5. Database construction: Routers build a consistent link-state database.
  6. Shortest-path calculation: Run Dijkstra's algorithm to find shortest paths and install appropriate routes.

Illustrative weighted graph. For a numerical question, use the exact graph and edge weights supplied in the question paper.

Dijkstra's shortest-path algorithm

Dijkstra's algorithm finds shortest paths from one source vertex to all other vertices in a graph with non-negative edge weights.

  1. Set the source distance to 0 and all other distances to infinity.
  2. Mark all vertices unvisited.
  3. Select the unvisited vertex with the smallest tentative distance.
  4. For each unvisited neighbour, calculate: new distance = selected vertex distance + edge weight.
  5. If the new distance is smaller, update the neighbour's distance and predecessor.
  6. Mark the selected vertex visited and repeat until all reachable vertices are visited.
  7. Use predecessor links to reconstruct the shortest path to each destination.
Important: Dijkstra's algorithm assumes non-negative edge weights. It is used by link-state routing protocols such as OSPF and IS-IS. It is not the algorithm used by RIP.

Distance Vector versus Link State

Basis Distance Vector Link State
Knowledge Receives distance information from neighbours. Builds a topology map from link-state information.
Information exchanged Routes / distance vectors. Link-state advertisements.
Algorithm Bellman–Ford family. Dijkstra shortest-path-first.
Convergence Can be slower; loop/count-to-infinity issues can occur. Typically faster in well-designed areas, but requires database and SPF processing.
Resource use Generally simpler; depends on protocol. More memory and processing for topology database and SPF calculations.
Example RIP. OSPF, IS-IS.

11. Internet Routing Protocols

Internet routing is commonly divided into routing within an Autonomous System (AS) and routing between Autonomous Systems. An AS is a network or group of networks under a common administrative routing policy.

Protocol Category / algorithm Purpose and key points
RIP (Routing Information Protocol) Interior Gateway Protocol (IGP); distance vector. Uses hop count as its metric. Maximum usable distance is 15 hops; 16 represents unreachable. Simple, but limited for large networks.
OSPF (Open Shortest Path First) IGP; link state. Uses link-state advertisements and Dijkstra's SPF algorithm. Supports areas and cost-based path selection.
IS-IS IGP; link state. Distributes link-state information and calculates shortest paths; widely used in service-provider and large networks.
BGP (Border Gateway Protocol) Exterior Gateway Protocol (EGP); path vector. Exchanges reachability information between autonomous systems and supports policy-based inter-domain routing. Uses attributes such as AS_PATH and LOCAL_PREF in route selection.

IGP versus EGP

IGP EGP
Routes within one autonomous system. Exchanges routes between autonomous systems.
Examples: RIP, OSPF, IS-IS. Internet inter-domain routing uses BGP.
Often focuses on internal reachability and path cost. Strongly policy-oriented; path attributes and administrative policy matter.

12. Congestion and Congestion Control

Definition

Network congestion occurs when the traffic offered to network resources exceeds their available capacity. Routers may experience growing queues, increased delay, packet drops and reduced throughput. If congestion is severe, retransmissions can add further traffic and worsen the condition.

Causes

  • Too many packets arriving at a router or link at the same time.
  • Insufficient bandwidth or buffer space.
  • Speed mismatch between incoming and outgoing links.
  • Burst traffic and poorly controlled sending rates.
  • Unbalanced routing or bottleneck links.

Effects

  • Longer queueing delay and jitter.
  • Packet loss due to buffer overflow.
  • Retransmissions and unnecessary additional traffic.
  • Lower effective throughput and possible congestion collapse.

Congestion control approaches

Open-loop (prevention) Closed-loop (feedback)
Attempts to prevent congestion before it occurs, without depending on feedback about current congestion. Detects congestion and uses feedback to adjust traffic or network behaviour.
Examples: traffic shaping, admission policy, retransmission policy, window policy and resource reservation. Examples: backpressure, choke packets, explicit congestion notification and adaptive rate/window control.
Focuses on design and policies that reduce the likelihood of overload. Responds to congestion indications or measured network conditions.

Open-loop techniques

  1. Retransmission policy: Use suitable timers and selective retransmission to avoid unnecessary repeated packets.
  2. Window policy: Choose a flow-control window strategy that avoids injecting excessive traffic.
  3. Acknowledgement policy: Reduce unnecessary acknowledgements where appropriate.
  4. Discard policy: Decide which packets may be discarded during overload.
  5. Admission policy: Refuse new flows or virtual circuits when resources cannot support them.
  6. Traffic shaping: Regulate the rate and burstiness of traffic, for example using leaky bucket or token bucket mechanisms.

Closed-loop techniques

  1. Monitor: Detect queue growth, packet loss, delay or explicit congestion signals.
  2. Feedback: Inform the source or upstream routers that congestion is occurring.
  3. Adjust: Reduce sending rate, change the sending window, reroute traffic or apply another control action.
  4. Recover: Gradually increase the sending rate when congestion subsides.

DECbit

DECbit is an early explicit congestion notification approach. A router monitors its queue; when the average queue exceeds a threshold, it marks a congestion indication bit in packets. The destination reflects the indication in acknowledgements, allowing the sender to reduce its sending rate. The sender can then cautiously increase its rate when congestion indications are absent.

Random Early Detection (RED)

RED is an active queue management technique. Instead of waiting until a queue is full, a router calculates an average queue size. When the average is below a minimum threshold, packets are normally accepted. Between minimum and maximum thresholds, packets are dropped or marked with a probability that increases with the average queue size. At or above the maximum threshold, packets are generally dropped or marked more aggressively according to configuration.

Conceptual RED behaviour: probabilistic marking/dropping rises between the minimum and maximum average-queue thresholds. Actual curves depend on configuration.

DECbit RED
Uses an explicit congestion indication bit in packets. Uses average queue size to probabilistically mark or drop packets.
Feedback is conveyed to the sender through acknowledgements in the described scheme. Early marking/dropping signals congestion before the queue is full.
Sender adjusts its rate based on received congestion indications. Transport protocols can react to packet marks/losses according to their congestion-control behaviour.

13. Quality of Service (QoS)

Definition

Quality of Service (QoS) refers to a network's ability to provide predictable or differentiated service characteristics to selected traffic. QoS mechanisms classify traffic and manage resources so that applications with different requirements can receive appropriate treatment.

Important QoS parameters

Parameter Meaning Why it matters
Bandwidth / throughput Data rate or useful data delivered per unit time. Important for video, file transfer and high-volume applications.
Delay / latency Time taken for data to travel from source to destination. Low delay is important for voice, gaming and interactive applications.
Jitter Variation in packet delay. High jitter affects real-time audio and video unless buffered.
Packet loss Fraction or number of packets that fail to reach the destination. Loss degrades media quality and may trigger retransmissions.
Reliability Consistency and dependability of network delivery. Important for critical services and transactions.

QoS mechanisms

  • Classification: Identifies traffic flows or classes using addresses, ports, protocol or markings.
  • Marking: Labels packets so network devices can apply a chosen forwarding treatment, for example DSCP in IP.
  • Queuing and scheduling: Determines the order in which packets are transmitted; examples include priority queuing and weighted fair queuing.
  • Traffic shaping: Buffers and smooths bursts to conform to a configured traffic rate.
  • Policing: Measures traffic against a profile and may drop or remark traffic that exceeds it.
  • Admission control: Accepts a new flow only when adequate resources are available.
  • Congestion avoidance / AQM: Uses early marking or dropping to manage queue build-up.
  • Resource reservation: Reserves resources for flows where the architecture supports it.

Leaky Bucket and Token Bucket

Leaky Bucket Token Bucket
Packets enter a finite queue and leave at a relatively fixed output rate. Tokens are generated at a configured rate and stored up to a bucket capacity.
Excess packets may be discarded if the queue is full. A packet can be sent when enough tokens are available; saved tokens permit controlled bursts.
Produces a smoothed output rate. Controls average rate while allowing bursts within the token capacity.

14. Worked Numerical Examples and Practice

Example A: Uploaded question-bank subnetting problem

Question: An ISP grants 200.192.30.0/24. At least 6 subnets and 30 host addresses per subnet are required. Determine the subnet mask, slash notation and broadcast address of the first subnet.

  1. To create at least 6 subnets, borrow 3 bits: 23 = 8 subnets.
  2. New prefix = /24 + 3 = /27.
  3. Host bits remaining = 32 − 27 = 5; usable hosts = 25 − 2 = 30.
  4. Subnet mask = 255.255.255.224.
  5. Block size = 256 − 224 = 32. First subnet ranges from 200.192.30.0 to 200.192.30.31.
Answer: Subnet mask = 255.255.255.224; slash notation = /27; first subnet broadcast address = 200.192.30.31.

Example B: Dijkstra's algorithm — exam method

The MUSA question bank asks for a shortest-path solution using a supplied graph. The graph itself must be read from the actual question paper; do not substitute a different graph. Use this table format while solving:

Subnetting practice checklist

  • Find a prefix that satisfies both required subnet count and usable hosts.
  • Convert a prefix length into dotted-decimal subnet mask.
  • Calculate block size, network ID, first and last usable address, and broadcast address.
  • Check whether an address belongs to a given subnet.
  • Aggregate contiguous networks using the correct CIDR prefix.

Routing practice checklist

  • Build a routing table from a given topology and metric.
  • Perform Dijkstra step by step and show the permanent set at every iteration.
  • Explain link-state routing with an example.
  • Compare static and dynamic routing.
  • Classify RIP, OSPF, IS-IS and BGP by routing domain and algorithm family.
