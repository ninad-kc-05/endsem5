1. Nature and Characteristics of Software

Definition

Software is a collection of computer programs, procedures, data structures and associated documentation that instructs a computer system to perform specific tasks.

Nature of Software

  • Software is an intangible product consisting of logical instructions.
  • It is developed through engineering activities rather than manufactured like hardware.
  • Its major cost is associated with development and maintenance.
  • It can be modified to satisfy changing requirements.
  • It may be custom-built or assembled using reusable components.

Characteristics of Software

  1. Intangible: Software cannot be physically touched like hardware.
  2. Developed, not manufactured: Most cost is incurred during analysis, design, coding and testing. Copying software costs very little.
  3. Does not physically wear out: Software does not deteriorate through physical use, although changes and environmental conditions can introduce defects.
  4. Complexity: Large software systems contain many interacting components.
  5. Changeability: Software can be modified to meet new requirements.
  6. Reusability: Existing software components may be reused in other applications.
  7. Maintenance-intensive: Software requires continuous correction, adaptation and improvement.

2. Software Application Domains

Software is used in different areas of computing and business. Major application domains include:

  1. System Software: Provides services and control for computer hardware. Examples include operating systems, compilers and device drivers.
  2. Application Software: Performs specific user-oriented tasks such as accounting, word processing and inventory management.
  3. Engineering and Scientific Software: Performs calculations, simulations, modelling and scientific analysis.
  4. Embedded Software: Controls devices and machines such as automobiles, washing machines and medical equipment.
  5. Product-Line Software: Provides a set of related capabilities for a particular market or group of users.
  6. Web Applications: Applications accessed through web browsers, such as e-commerce platforms and online banking.
  7. Artificial Intelligence Software: Uses intelligent techniques such as machine learning, expert systems and natural language processing.

3. Software Engineering

Definition

Software Engineering is a systematic, disciplined and measurable approach to the development, operation, maintenance and evolution of software.

Need for Software Engineering

  1. Managing complexity: Large software systems contain many components and dependencies.
  2. Quality improvement: Defined processes, reviews and testing help improve reliability.
  3. Cost control: Estimation and planning help control development expenses.
  4. Time management: Scheduling helps teams complete work within deadlines.
  5. Requirement management: A systematic process helps handle changing customer needs.
  6. Team coordination: Defined responsibilities improve collaboration.
  7. Maintenance: Engineering practices make software easier to correct and enhance.
  8. Risk reduction: Potential problems can be identified and managed early.

Major Software Engineering Activities

  1. Communication: Understand customer requirements.
  2. Planning: Estimate effort, cost, resources and schedule.
  3. Modelling: Prepare analysis and design representations.
  4. Construction: Perform coding and testing.
  5. Deployment: Deliver the software and collect feedback.

4. Layered Approach of Software Engineering

Software Engineering is a layered technology consisting of four layers. Each layer supports the layer above it.

TOOLS
METHODS
PROCESS
QUALITY FOCUS

Layered technology of Software Engineering — Quality Focus is the foundation.

  1. Quality Focus: The foundation of Software Engineering. It emphasizes continuous improvement and the development of high-quality software.
  2. Process: Provides the framework that organizes software development activities and tasks.
  3. Methods: Provide technical procedures for requirement analysis, design, coding, testing and maintenance.
  4. Tools: Provide automated or semi-automated support for processes and methods.

Conclusion: The layered approach provides a systematic foundation for developing quality software using defined processes, methods and tools.

5. Software Process

Definition

A software process is a structured set of activities, actions and tasks required to develop and maintain a software product.

Major Activities

  1. Requirement Analysis: Understand customer needs and document the requirements.
  2. Design: Define architecture, modules, interfaces and data structures.
  3. Implementation: Convert the design into executable program code.
  4. Testing: Detect defects and verify that requirements are satisfied.
  5. Deployment: Deliver the software to the customer or operating environment.
  6. Maintenance: Correct defects, adapt the system and introduce improvements.

Elements of a Software Process

  • Activities and tasks
  • Work products and deliverables
  • Milestones
  • Quality assurance points
  • Roles and responsibilities

6. Generic Process Framework

The generic process framework provides a common structure for software development projects. It consists of five framework activities.

Communication→ Planning→ Modeling→ Construction→ Deployment

Feedback from deployment helps improve the next iteration.

  1. Communication: Communicate with stakeholders and gather requirements.
  2. Planning: Identify tasks, resources, responsibilities, risks and schedules.
  3. Modeling: Prepare analysis and design models of the proposed system.
  4. Construction: Generate program code and perform testing.
  5. Deployment: Deliver the software, obtain feedback and make improvements.
Important distinction: The five activities form the generic process framework. Umbrella activities operate across all these activities; they are not a separate final development phase.

7. Umbrella Activities

Definition

Umbrella activities are supporting activities performed throughout the software development process to manage quality, progress, risks, changes and project work products.

Eight Umbrella Activities

  1. Software Project Tracking and Control: Monitors project progress against the plan, identifies deviations and takes corrective action.
  2. Formal Technical Reviews (FTR): Reviews software work products to detect errors early and improve quality.
  3. Software Quality Assurance (SQA): Ensures that processes and products follow defined quality standards.
  4. Software Configuration Management (SCM): Controls changes, versions and configuration items throughout development.
  5. Document Preparation and Production: Prepares and maintains technical documents and project records.
  6. Reusability Management: Identifies and manages reusable software components.
  7. Measurement and Metrics: Collects measurements about products, processes and projects to support evaluation and improvement.
  8. Risk Management: Identifies, analyzes and manages uncertainties that may affect the project.

8. Capability Maturity Model (CMM)

Definition

Capability Maturity Model (CMM) is a framework used to assess and improve the maturity of an organization's software development process. It defines five maturity levels.

Level 5 — Optimizing
Level 4 — Managed
Level 3 — Defined
Level 2 — Repeatable
Level 1 — Initial

CMM maturity levels from lowest to highest.

Five Maturity Levels

Level 1 — Initial

  • Process is ad hoc and sometimes chaotic.
  • Success depends heavily on individual effort.
  • Cost, schedule and quality are unpredictable.

Level 2 — Repeatable

  • Basic project management practices are established.
  • Earlier successful practices can be repeated on similar projects.
  • Cost, schedule and requirements are tracked.

Level 3 — Defined

  • Processes are documented and standardized across the organization.
  • Projects follow approved organizational processes.
  • Roles and procedures are clearly defined.

Level 4 — Managed

  • Process and product quality are measured quantitatively.
  • Performance is controlled using measurements.
  • Results become more predictable.

Level 5 — Optimizing

  • Focus is on continuous process improvement.
  • Quantitative feedback is used to improve processes.
  • Preventive actions and new technologies may improve performance.

Memory keyword: I–R–D–M–O = Initial, Repeatable, Defined, Managed, Optimizing.

9. Capability Maturity Model Integration (CMMI)

CMMI is an integrated process-improvement framework developed to provide organizations with a more integrated approach to process improvement across different disciplines.

Features of CMMI

  • Integrates process-improvement guidance across relevant disciplines.
  • Helps organizations assess and improve their processes.
  • Encourages defined and managed processes.
  • Supports measurement and continuous improvement.
  • Builds on the process-maturity improvement approach associated with CMM.

CMM vs CMMI

10. Prescriptive Process Models

Prescriptive process models define an organized sequence of software engineering activities and tasks. They prescribe how development work should be structured and managed.

Major Prescriptive Models

  • Waterfall Model
  • V-Model
  • Incremental Model
  • Evolutionary Models
  • Spiral Model
  • Prototyping Model
  • RAD Model
  • Concurrent Model

The selection of a process model depends on requirement stability, project complexity, risk, customer feedback and delivery requirements.

11. Waterfall Model

Definition

The Waterfall Model is a linear sequential software development life-cycle model in which development proceeds through a series of defined phases.

Requirement Analysis↓ System Design↓ Implementation↓ Testing↓ Deployment↓ Maintenance

Phases

  1. Requirement Analysis: Gather, analyze and document user requirements.
  2. System Design: Prepare system architecture and detailed design.
  3. Implementation: Convert design into program code.
  4. Testing: Test the software and identify defects.
  5. Deployment: Deliver the software to the user.
  6. Maintenance: Correct defects and make required changes after delivery.

Advantages

  1. Simple and easy to understand.
  2. Clearly defined phases.
  3. Easy to manage when requirements are stable.
  4. Suitable for small projects with fixed requirements.

Disadvantages

  1. Not suitable for frequently changing requirements.
  2. Working software is generally available late.
  3. Changes in later phases can be costly.
  4. Defects may be identified relatively late.

Suitable for: Projects with well-understood and stable requirements.

12. V-Model

Definition

The V-Model is a software development model in which each development phase is associated with a corresponding testing phase. It emphasizes verification and validation.

Verification / DevelopmentValidation / Testing
Requirement AnalysisAcceptance Testing
System DesignSystem Testing
Architecture DesignIntegration Testing
Module DesignUnit Testing
CODING — Bottom of the V

Each development activity maps to its corresponding testing activity.

Verification Activities

  1. Requirement Analysis
  2. System Design
  3. Architecture / High-Level Design
  4. Module / Low-Level Design
  5. Coding

Validation and Testing Activities

  1. Unit Testing: Tests individual modules and is associated with module design.
  2. Integration Testing: Tests interactions between modules and is associated with architecture design.
  3. System Testing: Tests the complete system and is associated with system design.
  4. Acceptance Testing: Checks whether the software satisfies user requirements.

Verification: Are we building the product correctly?

Validation: Are we building the correct product?

Advantages

  • Testing is planned early.
  • Clear relationship between development and testing phases.
  • Defects can be identified systematically.
  • Suitable when requirements are clearly defined.

Disadvantages

  • Not flexible when requirements change.
  • Working software is generally available late.
  • Changes can require modification of multiple stages.

13. Incremental Process Model

Definition

The Incremental Model develops and delivers software in a series of increments. Each increment adds functionality to the previously delivered product.

Overall Requirements→ Increment 1
Core Product→ Increment 2
Added Features→ Increment 3
More Features

Working

  1. Identify and prioritize overall requirements.
  2. Plan the first increment.
  3. Design, implement and test it.
  4. Deliver the working increment.
  5. Obtain feedback and plan the next increment.
  6. Repeat until the required functionality is delivered.

Advantages

  • Working software is delivered early.
  • Customer feedback guides later increments.
  • Smaller increments are easier to test and debug.
  • Changes can be incorporated between increments.

Disadvantages

  • Careful planning and integration are required.
  • Architecture can become difficult to manage.
  • Poorly planned increments may increase cost.

14. Evolutionary Process Models

Definition

Evolutionary process models develop software through repeated versions. The product evolves as developers and customers gain a better understanding of requirements.

Characteristics

  • Development occurs through iterations or versions.
  • Customer feedback refines the product.
  • Requirements may evolve.
  • Early versions help identify missing functionality.

Advantages

  • Users can evaluate partially developed software.
  • Feedback improves later versions.
  • Core functionality can be tested early.
  • Unclear requirements may become clearer.

Disadvantages

  • Repeated changes may complicate planning.
  • Architecture may become difficult to maintain.
  • Cost and completion time may be harder to predict.

15. Spiral Model

Definition

The Spiral Model is a risk-driven evolutionary software process model. Development proceeds through repeated loops, with each loop involving objectives, risk analysis, development and planning.

1. Objective Setting→ 2. Risk Analysis
↓
4. Planning Next Cycle← 3. Development & Validation

The four activities repeat in successive spiral cycles.

Four Activities

  1. Objective Setting: Define objectives, alternatives and constraints.
  2. Risk Assessment and Reduction: Identify and analyze risks. Use prototypes or alternatives to reduce major risks.
  3. Development and Validation: Develop and test the next product version.
  4. Planning: Review results and plan the next iteration.

Advantages

  1. Strong focus on risk identification and management.
  2. Suitable for large and complex projects.
  3. Supports changing requirements.
  4. Customer feedback can be incorporated.
  5. Allows repeated evaluation of project risks.

Disadvantages

  1. Expensive and complex to manage.
  2. Requires expertise in risk analysis.
  3. Time and cost estimation can be difficult.
  4. Not generally suitable for small, low-risk projects.

Suitable for: Large, complex and high-risk projects.

16. Prototyping Model

Definition

The Prototyping Model creates an early working representation of the proposed software so that users can evaluate it and clarify requirements before final development.

Initial Requirements↓ Quick Design↓ Build Prototype↓ User Evaluation and Feedback↓ Refine Prototype ↺↓ Develop Final System↓ Testing and Deployment

Steps

  1. Gather initial requirements.
  2. Prepare a quick design.
  3. Build the prototype.
  4. Obtain user evaluation and feedback.
  5. Refine requirements and prototype.
  6. Repeat refinement as required.
  7. Develop and test the final system.

Advantages

  • Helps clarify unclear requirements.
  • Encourages early user involvement.
  • Identifies missing requirements.
  • Usability problems can be discovered early.

Disadvantages

  • Users may mistake the prototype for the completed product.
  • Repeated changes may increase cost and time.
  • Prototype architecture may not be suitable for the final system.
  • Directly converting a prototype into the final product may cause design compromises.

Suitable for: Projects with unclear requirements or systems requiring early user-interface evaluation.

17. Rapid Application Development (RAD) Model

Definition

Rapid Application Development (RAD) is an incremental software development model that emphasizes rapid development, reusable components, user involvement and quick delivery through time-boxed development cycles.

Phases of RAD Model

  1. Business Modelling: Identify business functions, information flow and the objectives of the application.
  2. Data Modelling: Identify the data objects required by the system and define their relationships.
  3. Process Modelling: Define the processes required to manipulate and transform the data.
  4. Application Generation: Build the application using reusable components and development tools.
  5. Testing and Turnover: Test the system, integrate components and deliver the application.
Business Modelling↓ Data Modelling↓ Process Modelling↓ Application Generation↓ Testing and Turnover

Advantages

  • Fast development and delivery.
  • High customer involvement.
  • Encourages component reuse.
  • Suitable for modular projects.
  • Early feedback helps improve the application.

Disadvantages

  • Requires skilled developers.
  • Requires continuous customer participation.
  • Not suitable for every large or highly complex system.
  • Requires modularization and appropriate tools.
  • Integration may become difficult if components are poorly coordinated.

Suitable for: Projects requiring rapid delivery, where requirements can be modularized and users are available for frequent feedback.

18. Concurrent Model

Definition

The Concurrent Model represents software engineering activities as states that may occur concurrently. Different activities can progress independently and change state in response to events.

Communication Modelling Construction Testing

Activities may overlap rather than follow one fixed sequence.

Characteristics

  • Communication, modelling, construction and testing may overlap.
  • Each activity can be in a different state at a given time.
  • Events cause activity-state transitions.
  • It supports parallel development activities.
  • It is not a simple one-way sequential model.

Advantages

  • Supports parallel work.
  • Can reduce overall development time.
  • Provides flexibility when activities overlap.
  • Suitable for projects with multiple interacting activities.

Disadvantages

  • Requires careful coordination.
  • Management can become complex.
  • Dependencies between activities must be monitored.

19. Agile Process Model

Definition

Agile is an iterative and incremental software development approach that emphasizes frequent delivery, customer collaboration, response to change and continuous feedback.

Product Backlog→ Planning→ Iteration→ Design & Build→ Testing→ Working Increment

Review and feedback guide the next iteration.

Characteristics

  1. Iterative and incremental development.
  2. Frequent delivery of working software.
  3. Customer collaboration.
  4. Flexible response to changing requirements.
  5. Continuous testing and feedback.
  6. Close team cooperation.

Four Agile Manifesto Values

  1. Individuals and interactions over processes and tools.
  2. Working software over comprehensive documentation.
  3. Customer collaboration over contract negotiation.
  4. Responding to change over following a plan.

The items on the right still have value; Agile emphasizes the items on the left more.

Twelve Agile Principles

  1. Satisfy customers through early and continuous delivery of valuable software.
  2. Welcome changing requirements, even late in development.
  3. Deliver working software frequently.
  4. Business people and developers work together throughout the project.
  5. Build projects around motivated individuals and support them.
  6. Prefer direct conversation for effective communication.
  7. Working software is the primary measure of progress.
  8. Maintain a sustainable development pace.
  9. Give continuous attention to technical excellence and good design.
  10. Simplicity is essential.
  11. Good architectures and designs emerge from self-organizing teams.
  12. Regularly reflect and adjust to improve team effectiveness.

Advantages

  • Early and frequent delivery.
  • Better customer involvement.
  • Easy response to changing requirements.
  • Continuous feedback.
  • Frequent testing and improvement.

Limitations

  • Requires regular customer collaboration.
  • Frequent changes can make scheduling difficult.
  • Requires disciplined communication.
  • May be difficult where fixed scope and extensive upfront documentation are mandatory.

20. Extreme Programming (XP)

Definition

Extreme Programming (XP) is an Agile development method that emphasizes frequent releases, customer involvement, continuous feedback and disciplined engineering practices.

Five Core Values

  1. Communication
  2. Simplicity
  3. Feedback
  4. Courage
  5. Respect

Important XP Practices

  1. Planning Game: Customer and developers prioritize features and plan releases.
  2. Small Releases: Deliver useful software frequently.
  3. Simple Design: Keep the design as simple as possible for current requirements.
  4. Testing: Perform continuous testing, including automated tests.
  5. Refactoring: Improve internal code structure without changing external behaviour.
  6. Pair Programming: Two developers work together at one workstation.
  7. Collective Code Ownership: Team members can improve any part of the code.
  8. Continuous Integration: Integrate and test changes frequently.
  9. On-Site Customer: Keep a customer representative available for feedback.
  10. Coding Standards: Follow shared coding conventions.
  11. Sustainable Pace: Avoid continuous excessive overtime.
  12. System Metaphor: Use a shared simple description of how the system works.

Typical XP Cycle

User Stories→ Planning→ Design→ Coding→ Testing→ Small Release

Advantages

  • Frequent feedback and releases.
  • Early defect detection.
  • Improved communication.
  • Adaptability to changing requirements.
  • Improved code structure through refactoring.

Limitations

  • Requires customer availability.
  • Requires strong team discipline.
  • Pair programming may not suit every team.
  • Scaling to large distributed teams can be challenging.

21. Scrum

Definition

Scrum is an Agile framework in which a team develops a product through fixed-length iterations called Sprints. Each Sprint aims to produce a usable product increment.

Scrum Accountabilities

  1. Product Owner: Maximizes product value and manages the Product Backlog.
  2. Scrum Master: Helps the team understand and apply Scrum and supports removal of impediments.
  3. Developers: Create the usable product increment during each Sprint.

Scrum Events

  1. Sprint: Fixed-length cycle in which work is performed.
  2. Sprint Planning: Establishes the Sprint Goal and plans the work.
  3. Daily Scrum: Daily event for Developers to inspect progress and adapt their plan.
  4. Sprint Review: Inspect the outcome with stakeholders and discuss adaptations.
  5. Sprint Retrospective: Identify improvements to team effectiveness and quality.

Scrum Artifacts

  1. Product Backlog: Ordered list of work needed to improve the product.
  2. Sprint Backlog: Sprint Goal, selected Product Backlog items and delivery plan.
  3. Increment: Usable step toward the product goal that meets the Definition of Done.

Scrum Lifecycle

Product Backlog↓ Sprint Planning↓ Sprint Backlog↓ Sprint: Design · Develop · Test↓ Usable Increment↓ Sprint Review↓ Sprint Retrospective↺ Next Sprint

Daily Scrum takes place throughout the Sprint.

Advantages

  • Regular delivery of usable increments.
  • Clear accountabilities and events.
  • Frequent inspection and adaptation.
  • Transparency and continuous improvement.

Limitations

  • Requires active team participation.
  • Poor backlog management reduces effectiveness.
  • Requires consistent understanding of Scrum practices.

22. Kanban

Definition

Kanban is a method for managing and improving workflow by visualizing work, limiting work in progress (WIP) and managing the flow of tasks.

Main Principles

  1. Visualize workflow.
  2. Limit work in progress.
  3. Manage and improve flow.
  4. Make workflow policies explicit.
  5. Use feedback loops.
  6. Improve collaboratively and evolve experimentally.

Example Kanban Board

To DoIn ProgressTestingDone
Task ATask CTask DTask F
Task BTask E

Illustrative Kanban board showing the movement of tasks through workflow stages.

Advantages

  • Work status is clearly visible.
  • Bottlenecks can be identified.
  • WIP limits control parallel work.
  • Supports continuous delivery.
  • Allows flexible priorities.

Limitations

  • The board must be kept updated.
  • Without WIP limits it can become only a task list.
  • Delivery timing is less fixed than Sprint-based Scrum.

24. Advanced Trends in Software Engineering

Software Engineering continues to evolve due to changes in technology, development practices and user requirements. Important trends include:

  1. Artificial Intelligence and Machine Learning: Used for intelligent applications, prediction, automated testing and defect detection.
  2. Cloud Computing: Provides computing resources, storage and software services over the internet.
  3. DevOps: Combines development and operations practices to improve collaboration, automation and software delivery.
  4. Microservices Architecture: Divides an application into smaller, independently deployable services.
  5. Internet of Things (IoT): Connects physical devices that collect and exchange data through networks.
  6. Low-Code and No-Code Development: Uses visual tools and predefined components to accelerate application development.
  7. Cybersecurity Engineering: Integrates security practices throughout the software development life cycle.
  8. Continuous Integration and Continuous Delivery: Automates integration, testing and delivery activities.
